Historical review of 16d26c95. Findings and line references in the sections before `Current branch review` describe that revision. The current status appears below.

## Summary

The core of the PR is the right foundation for the rest of #24: turn policy pinned at admission, queued work carrying its snapshot, FIFO setter barriers that commit only on success, root batching and interrupt folding stopping at generation boundaries, and removal of mid-run settings adoption. `PolicyUpdateTicket` (reserve, prepare outside the lock, commit under the state lock, cancel on drop) is close to a general transition primitive, and later work (#123, rewind, fresh-context transitions) can build on it. No await-under-lock or lock-order problems were found; the order is state, then queue, then completion throughout.

Two structural problems should be resolved before merge, and the restrictive-effects half of step 4 introduces most of the regressions listed below. The recommendation is to split the PR: merge the configuration, admission and barrier core, and defer the Lua host-effect sandbox to PR 7/8A, where the policy fields become generic.

## Structural issues

### The coordinator is still the owner of model and options

`change_model` commits through `coordinator.set_option("model")`, which updates the provider slot and session meta (`event_loop.rs:3546-3557`). The actor ticket is resolved afterwards by reading the slot back through `policy_from_coordinator` (`event_loop.rs:547-571`). The actor configuration is therefore a projection of the coordinator, which is the reverse of plan step 2 ("session meta-mode/model as projections of root configuration"). Consequences:

- `maki.session.set_option` (`maki-lua/src/api/session.rs:439`) and the `session_option:set` routes call the coordinator directly. `sync_actor_policy` is not called on that path, so the status bar shows the new model or fast/thinking setting while every later turn runs with the old policy. Before this PR, `SessionRunSettings` read live values, so this is a regression.
- `cancel_existing` marks every pending setter `PolicyCancelled` (`actor/mod.rs:1084-1090`), and cancel-all reaches it through `cancel_subtree`. The UI setter has already awaited the coordinator op, which wrote the new model to the slot and session meta. After `/model X` during a turn followed by cancel-all, the UI and session show X and the actor keeps the old model until another setter runs. Cancelling queued work should not cancel configuration changes.
- The UI `SetterSequence` (`event_loop.rs:643`) is a second sequencer on top of the actor's `pending_policy` queue.
- A prepare step cannot be side-effect-free while the slot changes before the barrier commits, which blocks cancellable model switches.

Suggested direction: setters prepare a `RunSettings` value (provider built, nothing committed), resolve the actor ticket, and the coordinator, provider slot and session meta project from the committed actor configuration. `SetterSequence` is then unnecessary.

### Mode is not part of agent configuration

`EffectiveAgentConfig` is an alias of `RunSettings` (`actor/types.rs:22`) and covers provider, model, fast, workflow and thinking. Mode travels on each `AgentInput`, and the mode definition, tool bindings and prompt inputs are captured by a separate backend closure (`AdmissionPreparation`, `actor/types.rs:216`) without a generation. There are three snapshot paths: actor policy, the admission closure, and headless `QueuedInput` (`headless.rs:593`). The #24 requirement that a mode switch can be reverted, with the mode reverting accordingly, needs mode in the same versioned configuration that barriers commit. Suggested direction: make `EffectiveAgentConfig` a struct containing mode and the resolved `ModeDef`, route mode changes through the same ticket, and stop reading mode from `AgentInput` at admission.

A related point: admission is not a pure capture. The TUI `admission_preparation` reads instruction files synchronously on the UI thread and spawns a detached task to resolve prompt slots and MCP prompts (`agent_loop.rs:509-574`).

## Bugs

Ordered by severity.

1. Plan mode cannot write its plan file on macOS. `write_plan` returns `PermissionDenied` on non-Linux targets (`maki-lua/src/api/fs/mod.rs:170-186`), and the bundled write and edit tools use `maki.fs.atomic_write`. macOS is a release target. rustix provides `openat`, `mkdirat`, `renameat` and `O_NOFOLLOW` on macOS, so `cfg(unix)` is available.
2. Plan-file writes fail on Linux when any ancestor of the plan path is a symlink. `anchored_plan_write` applies `O_NOFOLLOW` to every component from `/` (`fs/real.rs`). Fedora Atomic (`/home -> var/home`) and a symlinked `XDG_STATE_HOME` both fail with `ELOOP`. Resolving the host-created plans directory once and anchoring below it fixes this and the macOS case.
3. Plan mode skips all plugin tool hooks. `Hook::of` returns `None` whenever `restrict_write_to()` is set (`agent/tool_dispatch.rs:145-148`), so input and output hooks are skipped for every tool, including reads. A guard plugin that denies reading `.env` stops working when the user switches to plan mode. The plan asked for a recheck after the input hook rewrites arguments, not for hooks to be disabled. The test `restricted_write_never_reaches_input_hooks_even_for_plan_path` fixes this behaviour in place.
4. Any MCP state change during a turn invalidates every pinned MCP binding, in all modes. `binding_is_current` requires `snapshot.generation == binding.generation` (`mcp/mod.rs:694`), and the generation increments on every manager step (`mcp/mod.rs:1062`, `1067`, `1205`), including an unrelated server finishing its connection. Every tool from an already-connected server then returns "unavailable tool" and disappears from the advertised list mid-turn, which also invalidates the prompt cache. Transport identity plus raw name already detects a replaced binding. `ToolSearch` has the same problem with `ptr_eq` on the published state.
5. ACP `session/prompt` sent immediately after `session/new` or `load` can fail with -32603 "session ended". `InteractiveInputSender::send` returns `Err` while `SharedModel` is empty (`headless.rs:623-635`), and the model is seeded only after `from_model_async` completes in the spawned task (`headless.rs:799-811`). Before this PR the input queued. The ACP test avoids the race by waiting for readiness (`maki-acp/src/server.rs:4852-4867`), and `with_input_mirror` bypasses the settings path.
6. Managed `task` fails in custom modes without `restrict_write_to`. `child_mode` is `Build` unless the parent is restrictive (`maki-lua/src/api/agent.rs:1132-1152`), but the manager sets `mode_ceiling = Some(parent_mode)` (`manager/mod.rs:429`) and `admit_turn_locked` requires an exact mode match, so every child prompt returns `PolicyCeiling`. In the other direction, a custom mode with a tool whitelist and no write restriction would give children `Build` if the manager check were absent. `rush`/`rush_locked` check `mode != Build` instead of equality (`actor/mod.rs:778-806`), which is inconsistent with admission. The Lua backend ignores `context.policy` and runs with its own `params.model`, so a child's recorded policy does not match the model it executes with.
7. `task` with `output_schema` does not work in plan mode. The child's `structured_output` local tool is added to `allowed`, but `mode_offers` only accepts bundled native routes under `restrict_write_to` (`tool_dispatch.rs:359`), so the tool is never advertised and the child cannot commit its result.
8. Plugin callbacks lose host effects in build mode. `run_restricted_callback` (`runtime.rs` ~1083) sets `restrict_effects = true` regardless of mode, so header, `permission_scopes` and `mutable_path` callbacks, and async tasks they spawn, lose fs writes, jobs, network and timers in unrestricted mode. This affects third-party plugins and is undocumented.
9. Settings changes that do not change settings still create barriers. `flush_policy_updates` bumps the generation on every successful resolve (`actor/mod.rs:289-295`), and `dispatch_option_toggle` reserves for every option, YOLO included. After toggling YOLO mid-turn, later messages no longer batch or fold into the running turn. `SetterSequence` also chains `DirectoryChanged`, which the coordinator defers behind the lease, so `/cd` then `/yolo` during a turn delays YOLO until the turn ends and loses the "YOLO reaches the prompting turn" behaviour (`session_coordinator.rs:952-956`).
10. Idle compaction ignores its pinned policy. `push_compact` pins generation and policy (`actor/mod.rs:932-937`) but the TUI compaction reads the live `model_slot` (`agent_loop.rs:692`). `push_compact` also skips the reservation check, so a compaction requested after a setter reservation runs ahead of deferred work with the old generation. `compact_keeps_admitted_policy` passes because `ScriptedBackend` records `context.policy`, not because the TUI backend uses it.
11. Headless re-captures bindings after `mcp.ready()` (`headless.rs:995-1001`), which undoes the admission pin for queued inputs. `send_with_settings` builds the system prompt and reads `mode_def` from the mutable registry separately (`headless.rs:670-690`); `build_system_prompt_with_def` avoids the mismatch.
12. The new batch-key filter in `pop_interrupt` compares keys with `==` (`actor/queue.rs:279-281`). `batch_key` returns `None` for inputs with a prompt, cancel or lease committer, so when the active turn's key is `None`, a queued root of that kind still folds into it as a plain interrupt. This also happened before the PR, when `pop_interrupt` had no key check, but the new filter appears intended to prevent it. `None` should mean the root never folds.
13. Mid-turn thinking, fast and model changes now apply only to later turns, but the status bar, usage display and the "Thinking: X" flash update immediately. `note_if_deferred` exists and is only used for `cd`. The adopter comment at `maki-acp/src/server.rs:925-928` ("lands on the run's next request") is now incorrect.
14. Smaller items:
    - `update_policy` fails with `PolicyPending` while any reservation is outstanding, and the refined-model sync (`event_loop.rs:1932`) only logs the warning, so the refinement is lost if that reservation is cancelled.
    - `ActorSnapshot.queued` counts barriers.
    - A setter that never resolves (a hung provider initialisation) blocks all later admissions, and only cancel-all releases them.
    - The permissions docs flowchart drops the "plan file write runs" step, but `permissions.rs:469` still auto-allows it.
    - Plan mode loses `index`, `websearch` (while `webfetch` stays), `skill`, `todo_write`, `memory`, batch and `code_execution`. The `websearch`/`webfetch` split and the loss of `skill` look unintended.
    - Relative `restrict_write_to` paths never match in `mutation_allowed`, because the target is made absolute against the process cwd while the plan path is not. This fails closed but disagrees with the agent-level check, which resolves against `ctx.cwd`.
    - The headless `maki.model.get()` fallback returns `RequestOptions::default()` instead of the session's options.

## Scope

The plan describes an effect contract (`ReadOnly`, `FileMutation`, `DelegatedComposite`, `Spawn`, `UnknownMutation`). The implementation does not contain one. Restrictive mode is `restrict_write_to().is_some()`, and classification is a set of hard-coded bundled tool names (`tools/registry.rs:265-287`), duplicated in `loader.rs:491` and `runtime.rs:3604` with different keys (plugin name in one, tool name in another). The plan states that bundled Lua callbacks should not be whitelisted because they ship in-tree. `task` is classified read-only although it spawns children.

`plan_write_path` and `restrict_effects` are threaded through `TaskCell`, `PendingAsyncTask`, timers, `jobstart`, `net`, and `mode.define/set/reset`, about 70 references. Because the dispatcher already denies every non-bundled, local and MCP route in restrictive mode, the gating in keymap, slot, autocmd, ui, session_option and tool registration only ever applies to the bundled write and edit tools. The Lua-level policy is also not a hard boundary: a restricted handler can store a closure that an autocmd or load-time timer later runs without policy. The dispatcher check provides the actual guarantee. The later commits "Close restrictive policy escape paths" and "Preserve restrictive delegation ceilings" each patch this layer again.

PR 8A moves plan-file handling and write restrictions into guest code, so this layer is likely to be removed. Keeping the existing `restrict_write_to` check at native dispatch is enough for this PR. If an anchored write is kept, anchoring below the resolved plans directory under `cfg(unix)` covers the realistic threat, since a plan-mode turn has no shell or MCP access with which to plant a symlink.

## Simplification

- Remove `ActorWork::PolicyBarrier`. The per-root `generation` already separates batches and interrupts. A generation check for `Compact` in `pop_interrupt` covers the remaining case, and the special cases in `is_empty`, `publish_if_empty`, `remove_at`, the queue projection and `shared_queue.rs` go away.
- Remove aliases and no-op API: `effective_config`/`policy_snapshot` and `update_policy`/`set_effective_config` (`actor/mod.rs:818-886`); `admit_turn_after_policy` and `rush_after_policy` return `std::future::ready` of the synchronous call (`actor/mod.rs:855-866`), and the "unpolled future" tests exercise only that wrapper; `wait_policy_updates` is test-only; `RunSettingsSource`, `tool_builder` and `adopt_settings` have no production caller now that every caller passes `None`.
- `policy_from_coordinator` (`event_loop.rs:547-571`) duplicates `SessionRunSettings::current` (`run.rs:139-170`).
- `dispatch_session_op` and `dispatch_option_toggle` repeat the reserve, op, resolve/cancel block.
- Tool dispatch resolves the live route and then compares it with the pinned route up to five times per native call. Executing the pinned `TurnToolRoute` after a single currency check matches the plan's "execute that exact route" and removes most of `binding_matches`.
- `admit_turn`'s deferred branch repeats the mode-ceiling and precancel logic of `admit_turn_locked`.
- `spawn_child_with` calls `validate_manager` twice, and `validate_active` repeats checks done in the graph-lock block (`manager/mod.rs:312-345`). The hand-built `RunSettings` copy can be `(**snap).clone()`.
- `write_plan` checks the backend's `TypeId`, which required an `Any` supertrait on `FsBackend`. An `FsBackend::plan_write` method with a fail-closed default does the same.
- Dead code: `McpSession::generation()` and `McpSession::tool_binding()` have no callers, `authorize_mode`'s `_input` is unused, and the `local_map.keys()` extension in the restrictive child path has no effect.
- The child "ceiling" is an equality check that the Lua backend does not honour. It could be removed until PR 7 defines a narrowing rule.

## Recommended changes before merge

1. Split out the restrictive-effects sandbox, anchored writes and bundled allowlists. Keep the existing `restrict_write_to` dispatch check.
2. Invert ownership so the actor commits configuration and the coordinator, slot and session meta project from it. Remove `SetterSequence`.
3. Move mode and the resolved `ModeDef` into `EffectiveAgentConfig`, set through the same ticket.
4. Fix bugs 4, 5 and 9 to 13. Item 1 removes bugs 1 to 3, 7 and 8, item 2 removes the Lua `set_option` and cancel-all desyncs, and removing the child ceiling until PR 7 removes bug 6.
5. Remove `PolicyBarrier`, the aliases and the no-op futures.
