# Shared model-option specification and plan approval

## Goal

Resolve [lun-4/makima#172](https://github.com/lun-4/makima/issues/172) with one model picker for model identity and its options. The picker shows only options supported by the highlighted model. The picker, command completion, selection summaries, and model-change paths use shared option definitions and capability projection rather than separate thinking/fast implementations. Plan approval stages the structured selection and commits it atomically with implementation mode.

## Implementation Summary

The operator requires one interface for ordinary model changes and plan approval, with all controls inside the model picker. The operator also requires low redundancy: adding an option must not require branches in the picker, completion, plan form, approval transport, and each frontend's patch construction.

Retain typed `ModelSelection` as the partial request and `CompleteModelSelection` as the complete result. Add a small shared descriptor registry next to the partial selection in `maki-domain`. Descriptors define keys, labels, presets, free-input support, parsing, typed-field access, value formatting, and availability over a typed capability projection. `maki-providers` projects its resolved `Model` into these UI-neutral capabilities. Generic consumers use the same descriptors and capabilities for controls, completions, and summaries. Command execution and completion call one shared model identity-resolution helper in `maki-agent::command`. Centralize selection-to-`ConfigPatch` conversion in `maki-agent` and reuse it across structured model-change paths.

Primary files:

- `maki-domain/src/selection.rs`, `maki-domain/src/lib.rs`, and relevant provider re-exports: option descriptors and generic selection operations.
- `maki-providers/src/selection.rs`: complete-selection projection through the shared descriptors and projection of provider-adjusted model capabilities.
- `maki-ui/src/components/{model_picker,list_picker,arg_completion,plan_form,mod,keybindings}.rs`: generic picker controls, structured staging/actions, completion, and rendering.
- `maki-ui/src/model_capabilities.rs` (new), `maki-ui/src/command_runtime.rs`, and module registration: shared asynchronous capability resolver and contextual completion wiring.
- `maki-ui/src/app/{mod,view,mode,tests}.rs`, `maki-ui/src/event_loop.rs`, and `maki-ui/src/event_loop/approval.rs`: target ownership, capability event delivery/invalidation, application, and approval.
- `maki-agent/src/{config_change,session_coordinator,command}.rs` and `maki-agent/src/actor/config.rs`: one typed patch conversion, shared model identity resolution, and structured forwarding.
- `maki-lua/src/orchestration/command_host.rs` and `maki-lua/src/api/agent/handles/agent_methods.rs`: reuse the patch conversion while preserving authorization and publication checks.
- Documentation sources in `maki-docgen/src/gen_{commands,providers,keybindings}.rs`, keybinding metadata, and hand-written `site/docs/content/modes/_index.md`.

No new dependency or persistence schema is required. Do not redesign tier profiles (#89), migrate plan-mode ownership (#24), change model-option syntax or capability semantics, replace unrelated pickers, introduce untyped option maps, or build a general code-generation framework.

## Implementation Plan

### 1. Define model-option metadata and field operations once

Current duplication is concrete: `ModelSelection::set_option` matches keys in `maki-domain/src/selection.rs`; `ModelArgSource` repeats keys/presets in `maki-ui/src/components/arg_completion.rs:238`; the proposed picker would otherwise repeat that knowledge. The existing `ThinkingConfig`, `THINKING_METADATA`, `THINKING_OPTIONS`, `parse_thinking`, and `parse_fast` already supply the value semantics.

Add a static `ModelOptionSpec` descriptor registry in `maki-domain/src/selection.rs`. Each descriptor supplies:

- Canonical key, human-readable label, and description.
- Canonical preset values and their labels, with an explicit free-input flag or small value-kind enum.
- A reader returning the canonical textual representation of its optional typed field from `ModelSelection`.
- A replacement operation that parses a supplied value into that typed field, or clears it for an omitted value.
- An availability callback over a UI-neutral typed capability projection. It returns available, pending, or unavailable with an optional explanation. This callback belongs to the descriptor; consumers do not match option keys to capabilities.

Implement these with small typed callbacks and a descriptor constructor where useful. Keep `ModelSelection`'s named typed fields and wire shape. Reuse existing parse/display functions; do not add a second parser or option-value enum inside the UI. Thinking is a free-input field with presets. Fast is a closed choice using canonical `true`/`false` values. These differences are descriptor data, not option-key branches in consumer code.

Expose generic descriptor lookup, field read/replace/clear, iteration over present fields in registry order, empty-selection detection, and formatting of explicit assignments. Keep `ModelSelection::set_option` duplicate-rejecting for command and structured inputs, but delegate lookup, presence checks, and parsing to descriptors. Draft editing uses replacement rather than the duplicate-rejecting setter. An empty editor value clears its override; explicit `off` and `false` remain present even when equal to current values.

Remove the second field inventory in the custom deserializer's `Raw` struct. Visit input keys, handle identity separately, and route every known option through the registry and `set_option`. Preserve accepted text/numeric/bool forms, thinking aliases, omission/null behavior, strict unknown-key rejection, duplicate-key rejection (including duplicate null-valued keys), and useful existing errors. Keep typed serialization annotations and complete-result compatibility. Tests must compare old supported inputs and failure cases explicitly.

Add a small UI-neutral capability value beside the descriptors, with typed thinking support/requirement and tri-state fast support. Keep it separate from `ModelSelection`: capabilities describe available controls, not requested values. `maki-providers/src/selection.rs` converts an already provider-adjusted `Model` with `supports_thinking()`, `requires_thinking()`, `supports_fast()`, and `fast_pending()`. Fast is available only on confirmed support. Missing provider resolution produces an unresolved status with no editable option controls, not a guessed capability set. Descriptor callbacks map these typed capabilities to availability and explanatory text. Do not create a reverse dependency from `maki-domain` to providers, duplicate provider/model-ID rules, or alter parser and actor acceptance rules.

`CompleteModelSelection` remains a typed complete result in `maki-providers/src/selection.rs`. Expose its option values through the shared descriptor reader over a converted typed selection. A complete value used for display must never populate the partial request by accident. No option-specific formatting should remain in the picker or plan summary.

Replace the explicit thinking/fast tuple array in `ModelArgSource` with descriptor iteration. Preserve duplicate suppression, brace/trailing argument ranges, pinned-target filtering, and fuzzy matching. Use a generic `/model` argument hint (`[spec] [key=value ...]`) in `maki-commands/src/spec.rs` and a consistent generic `NONINTERACTIVE_MODEL_USAGE` in `maki-agent/src/command.rs`. Replace that file's exhaustive spec-only `ModelSelection { spec: Some(spec), thinking: None, fast: None }` routing match with a descriptor-backed `has_option_overrides()` check: route to `SetModel` only when identity is present and there are no registered option overrides; otherwise retain the full request in `SelectModel`. Do not add `..` to the match, since that could silently drop future options. Audit compatibility exports such as `MODEL_OPTION_KEYS`: derive retained key lists from the registry instead of maintaining a separate inventory. Generate an option reference table in `maki-docgen/src/gen_commands.rs` from descriptors rather than maintaining another supported-key list. Examples can name actual options.

Do not merge this registry with `SessionOptionDefinition`. That registry also covers workflow, YOLO, and plugin options and uses compatibility values `enabled`/`disabled`. Preserve those strings and ownership semantics. Reuse shared labels/descriptions/presets in its model-related definitions through explicit compatibility adapters; keep the existing boolean vocabulary adapter and legacy toggle behavior. Do not put plugin/session options into model selections merely because they share a registry category.

### 2. Centralize structured-selection application

The same field mapping currently occurs in `EventLoop::dispatch_model_selection`, `SessionCoordinatorHandle::set_model_with_claim`, `maki-lua/src/orchestration/command_host.rs::select_model`, and Lua `Agent:set_model`. Approval must not add another copy.

Add one typed conversion in `maki-agent`, for example `ConfigPatch::from_model_selection(&ModelSelection)`, containing the mapping of partial option fields to `ConfigPatch`. Add `config_change::prepare_selection(&ModelSelection, policy, prepare)` that uses this conversion and the existing `prepare_patch`/`prepare_model` for optional identity. Preserve `prepare_patch` for non-selection callers.

Migrate structured callers to these helpers:

- Ordinary TUI dispatch and approval call `prepare_selection` instead of constructing patches field by field.
- Orchestration command dispatch does the same inside its existing reserved transaction.
- `SessionCoordinatorHandle::set_model` and `set_model_with_claim` accept `ModelSelection` rather than separate spec/fast/thinking arguments. Update headless command forwarding and callers/tests. Internal legacy session-option setters can keep their compatibility adapters.
- Lua `Agent:set_model` uses the common patch conversion and attaches the model prepared by its existing provider/context path. Do not alter its target authorization, predecessor handling, policy, publication claim, Lua `(value, err)` return convention, or complete normalized return value. Avoid partially moving `selection.spec` before the conversion.

Do not centralize distinct transaction orchestration or authorization protocols merely to share field mapping. The helper is a typed conversion/preparation boundary, not a new configuration manager. Typed runtime options and provider capability validation remain in their owning layers.

Extension contract: adding a model option of an existing control kind must not require changes to picker fields/focus/rendering, completion, summary/reset logic, staging/approval transport, or patch building in each frontend. It requires the typed partial field/descriptor and availability callback, complete/runtime field, the single backend mapping, and domain-specific capability projection/provider/persistence changes where applicable. A genuinely new value kind may require one generic control implementation. Do not promise automatic provider support or replace typed storage with strings.

### 3. Preserve the existing partial-selection semantics

Reuse `maki-agent/src/actor/config.rs::ConfigChange::apply` and `maki-providers/src/types.rs::RequestOptions::clamped` without changing behavior:

- Omitted identity uses the addressed actor's preceding model/provider.
- Omitted options preserve the addressed actor's preceding values, subject to capability normalization. Do not freeze values captured when a picker opened.
- Explicit disabled values are distinct from omission, including when equal to current values.
- Model-only changes preserve supported inherited values. Unsupported inherited values normalize off. Required-thinking models promote off to minimal effort, as they already do.
- Unsupported explicitly enabled values are rejected rather than silently discarded.
- Model identity policy is checked against the addressed agent's policy at application/approval time. Discovery is not authorization.

Use `ModelSelection::default()` for no staged overrides in `PlanForm`, without an outer `Option`. Reset the whole selection generically for `Use current model`, leaving parallel and actor state unchanged. Replace string accessors with structured accessors. Identity cleanup can remove only redundant identity, never explicit option fields. Detect nonempty option staging using generic descriptor operations rather than checking thinking/fast individually.

### 4. Resolve capabilities once for picker and completion

Add a small `ModelCapabilityResolver` in `maki-ui/src/model_capabilities.rs` and hold the same `Arc` in `CommandRuntime` and `ModelArgSource`. Construct it once in `EventLoop::new` from the existing `model_preparer(prepare_provider, timeouts)`. That adapter runs provider creation in `smol::unblock` (`maki-ui/src/event_loop.rs:4424`). Do not expose the coordinator's private preparer or add synchronous provider work to render, filtering, or key handling.

The resolver accepts a pinned `TrustedTarget`, optional exact candidate spec, metadata revision, and cancellation for the caller's wait. Each request validates target liveness and the target template's model policy, including cache hits. Capture `target.actor()?.config_snapshot()` once and derive the source config, actor identity, and generation from that same `ConfigCommit` (`maki-agent/src/actor/mod.rs:2242`); do not pair independently read config and generation. Never substitute the root seed slot or newly focused target. Omitted identity uses that snapshot. For the same identity, use the already provider-adjusted model without constructing another provider. On metadata invalidation, refresh it with the existing `rediscovered_model` helper and its existing provider before projecting; the TUI discovery event can precede the catalog's asynchronous actor refresh. For a different identity, call `config_change::prepare_model` with the candidate spec, the target policy, and the shared preparer, then project `PreparedModel.model`. Preparation is a preview only: no actor reservation/commit, session mutation, prefs, or recents update. Do not retain a preview provider for later commits.

Cache and share in-flight compact projection results by pinned manager/agent identity, exact spec, source config generation/provider identity, and metadata revision. Bound retained results to live target contexts and the current metadata revision; clear superseded contexts instead of introducing a general cache framework. Policy and liveness checks still run before returning cached values. A cancelled caller stops waiting and cannot publish. Underlying `smol::unblock` work may finish, but an obsolete result cannot become the current projection. Unresolved/error state exposes no editable options. Model-only confirmation without explicit overrides remains possible and undergoes ordinary commit preparation/validation.

Add a resolver metadata revision advanced on every `InternalEvent::ModelsDiscovered`, before picker/completion refresh. This event occurs for each registered metadata batch, even if the spec list is unchanged. Invalidate on provider refresh/auth-context changes and committed target config changes too. `ModelCatalog::apply` refreshes attached actors on every batch but only republishes model values when specs grow (`maki-lua/src/orchestration/catalog.rs:138-194`); model-list equality is therefore insufficient. Preserve this catalog behavior, without creating a second actor-refresh mechanism.

Extend `OrchestrationRevision`/`orchestration_revision` in `maki-ui/src/event_loop.rs:1540-1587` with the active pinned picker's target liveness and coherent `ConfigCommit` stamp, even when it differs from the currently selected agent. The existing root config receiver and selected-config comparison do not observe an unfocused pinned child. Compare the pinned stamp in `matches`; a changed stamp invalidates the visible projection and schedules a fresh request, while a closed target retires the picker. Use the existing revision polling and sync path rather than a second observer system. Restart affected completion requests through their existing refresh path. No-op revisions must not reprepare providers.

Picker requests start on open, changed highlighted identity, or invalidation, outside `view`. Use a per-picker request generation and cancel/retire the previous waiter. Deliver a capability-ready internal event carrying session/runtime identity, pinned target, picker generation, spec, source config identity/generation, and metadata revision. Apply only while the same picker/target/spec/context remains active. Close, reopen, target retirement, and form-owner changes invalidate the generation. Mark dirty only for changed projection/status and retain idle repaint behavior. Pre-binding App fixtures receive a local supplied baseline/projection or an injected resolver; a missing live target never gets a root fallback.

Expose the existing private `resolve_model` in `maki-agent/src/command.rs:395-419` as the shared `pub fn resolve_model_spec(argument: &str, specs: &[Arc<str>]) -> Result<Arc<str>, CommandError>`. Rename with symbol-aware tooling during implementation and keep the implementation and errors unchanged. Command execution and completion must both call this function. Do not copy its exact/fuzzy branch, candidate fields, or ambiguity handling into the UI. The helper validates fully qualified syntax and preserves slash-containing identities verbatim, independently of discovery. Only unqualified input uses `fuzzy_resolve_candidates` with its existing spec/provider/model-ID fields. It performs no provider preparation, host request, policy authorization, or configuration mutation. Callers supply the addressed target's policy-filtered candidates; the existing preparation boundary still checks exact-identity policy. Keep the helper in `maki-agent::command`, since `maki-ui` already depends on that crate; no new resolver framework or dependency is needed.

`ModelArgSource::complete` uses the shared identity helper, capability resolver, descriptor availability, and cancellation. Determine the identity token without executing a command or making host requests. Use `CompletionContext.arguments` and its byte range: for an embedded option, parse the raw prefix before its opening brace; for a trailing option, parse the prefix before the active argument range with `maki_commands::parse_model_selection`. Reuse tolerant lexing/ranges for incomplete input. Options-only text uses the pinned target's current identity; any explicit identity goes through `resolve_model_spec` with the target-policy-filtered specs. Run resolution inside the asynchronous completion work, not rendering/key handling; move any potentially blocking metadata lookup off the UI executor using the existing unblock adapter. Fully qualified identities absent from discovery remain valid candidates. Never fuzzy-redirect malformed or denied fully qualified input to another model. An identity-helper error suppresses option suggestions for that incomplete/invalid completion request without changing execution's errors. Ambiguous, malformed, denied, or unresolved identity must not fall back to the current/root model. Only available descriptors contribute keys/presets. Preserve duplicate suppression and existing completion-generation guards. Check cancellation, target/config context, and metadata revision again before publishing; refresh through `project_model_discovery`/`refresh_model_arguments` on metadata-only invalidation.

### 5. Project the option specification into the shared picker

Ordinary opens start with no overrides. Plan opens start with their previously staged partial selection. Preselect explicit draft identity or the current identity. Explicit staged identity different from the baseline starts unresolved until its own capability result arrives.

Build editor rows by iterating the descriptor slice and filtering by the highlighted model's projected availability. Maintain a generic collection of draft row values and focus over the currently visible controls, not fields or focus variants named `Thinking` and `Fast`. Raw text buffers are transient editor state; confirmation constructs one typed `ModelSelection` through the shared descriptor operations. No key strings, option-count constants, per-option matches, or direct `selection.thinking`/`selection.fast` access belongs in picker/summary/completion code.

Only available options get editable rows and focus stops. Unsupported options are absent, including for a model with no supported options. Pending capability resolution does not expose an enabled control. Show a compact pending/status message outside the editor rows when useful. Required thinking remains an available option; annotate that `off` normalizes to minimal effort using existing backend semantics. Do not invent provider-specific effort restrictions or remove accepted syntax.

Recompute visibility on highlight changes, capability results, and discovery/config refreshes, even when the model spec list is unchanged. Preserve draft values by descriptor identity. If the focused row disappears, return focus to the model list; remaining controls keep stable navigation order. Never silently clear a draft because its row becomes hidden.

A nonempty explicit draft for an unavailable or pending option blocks confirmation. List its descriptor label, requested value, and reason in a separate conflict summary, without rendering the unsupported editor. `Ctrl+R` explicitly clears only currently unavailable/pending overrides and their raw buffers, with a visible hint while conflicts exist. The user can instead highlight a supporting model. Switching back restores the untouched draft and its editor. This rule includes explicit disabled/equal-valued drafts and invalid nonempty raw text; omitted fields never block a model-only selection and retain backend normalization. Cancel preserves the prior plan stage. This draft behavior must not change the existing saved pending-fast preference lifecycle.

Controls derive from descriptor data:

- Free-input descriptors use single-line `TextBuffer` editing and preset cycling. Empty means `Use current`, with the current value shown for context. Up/Down cycle omission and the descriptor's presets; numeric/custom values remain editable.
- Closed-choice descriptors cycle omission and the descriptor's canonical choices with Space/Left/Right. Fast therefore displays inherited/true/false through the same code any other closed choice uses.
- Tab/Shift+Tab navigate the model list/search and every currently available generated option row. Character input, editing keys, and paste affect only the focused field. Tier shortcuts operate only with model-list focus. `Ctrl+R` handles unavailable-override reset before field/list input, and is a no-op without conflicts.
- Enter from any focus checks current capability conflicts, validates all remaining draft fields through shared setters, and confirms once. Unavailable/pending overrides or invalid input leave the picker, model highlight, search, and all drafts intact, showing the applicable conflict or field error. Validate before `ListPicker` can consume its state.
- Esc/Ctrl+C cancel the whole draft from any focus without actor mutation, plan staging, prefs, or recent-model changes. Existing explicit tier-assignment actions retain their separate persistence behavior.
- Show selected identity and requested option values before confirmation. Format the values through descriptors and distinguish omission from explicit disabled values.

Return `ModelPickerAction::Select(ModelSelection)`. Unchanged identity may be omitted; option overrides must retain their explicitness. Current-model options-only edits must work without discovery results.

Keep current identity, explicit staged identity, and the highlighted draft identity represented when absent from discovery, using a minimal fallback identity row without duplicates. Reopening an undiscovered staged model or refreshing after the highlighted model disappears must not select an unrelated first model. These rows are not authorization. A genuinely nonmatching search still cannot confirm.

Extend `ListPicker` with a minimal multi-line caller-supplied footer rendering API, for example `view_with_footer_lines`, rather than copying the renderer or adding model-specific fields. Existing footer builders/single-line callers retain their behavior. Compute actual footer height from available rows plus pending/conflict/error lines, reserve it before the list viewport, and constrain rendering to the popup. For a short terminal, show the focused option or blocking conflict and confirmation/cancellation/reset hints while allowing list space to shrink and option rows to scroll. The row count comes from the descriptor projection, not the current number of options.

Retain filtering, sections, recents, selected anchors, refresh, mouse scrolling, tier assignment, and idle repaint behavior. Draft row values and still-available focus survive refresh; a disappearing focused row returns focus to the model list. All overlay methods and paste routing cover the entire picker. Capability projection determines visible controls and local draft conflicts. It does not authorize changes or replace actor validation and request normalization.

## Risks, Blockers, and Required Decisions

- Resolved operator requirements: all model/option controls belong in one picker; unsupported options are hidden for the highlighted model; generic consumers derive from a shared specification and capability projection instead of special-casing thinking/fast.
- Provider adjustment and metadata-only refresh affect availability even when identity is unchanged. Resolution stays off the render/UI path, uses pinned-target context, rejects stale results, and never commits a preview. Pending fast support must not be flattened into confirmed availability or alter saved pending-fast preferences.
- Hiding an editor must not hide a staged request. The separate conflict summary and explicit `Ctrl+R` reset retain user intent while allowing model changes to proceed after reset.
- Keep descriptors small. Do not replace explicit typed public contracts with a dynamic map or introduce macro machinery to avoid legitimate backend field declarations. Runtime/provider/persistence changes remain necessary for genuinely new capabilities.
- The partial and complete serde shapes are public contracts, including scalar forms and errors. Registry-driven deserialization requires explicit compatibility tests for nulls/duplicates/unknowns, not only happy paths.
- Session-option metadata has different wire vocabulary and security scope. Reuse metadata through adapters without merging option universes or changing `enabled`/`disabled` values.
- A complete baseline must not freeze omitted fields. Redundant-identity cleanup must not erase explicit option overrides.
- Discovery is stale/non-authoritative; preserve selected fallback identities but validate under the addressed target's policy at commit time.
- Generic footer layout must handle a descriptor-derived number of controls and short terminals without changing unrelated pickers.
- Existing failed child-approval cleanup resets staging. Replace it with target-addressed pending-only cleanup and protect active/saved root/child variants in tests.
- Existing fixtures hard-code model-only requests and row counts. Preserve meaningful assertions while migrating them.
- No unresolved product decisions, accepted testing gaps, or known blockers remain. No project files changed and no commit is requested.
