# 42: Root-session `/goal`

## Goal

Ship a TUI-only `/goal` that keeps one root session working toward a user-set objective across at most ten qualifying root turns per allowance. The root model reports completion or blocking itself; ordinary input, subagent delivery, mode restrictions, and permission checks keep their normal behavior.

## Implementation Summary

Replace the bundled `plugins/goal` implementation wholesale on `luna.42-goal-plugin`; do not inspect or reuse the prior Goal draft or consult PRs. Use `investigation.md` for generic host references, not as the final product contract: the decisions below incorporate the subsequent user discussion, notably mid-turn activation, real queued announcements, normal prompts not pausing Goal, and replacement preserving the count. Keep the existing bundled plugin identity and config enable switch. Remove checker-specific options, prompts, and docs; use a single Lua reducer/controller with durable session records. No second verifier, new provider protocol, model-specific behavior, token cutoff, automatic failure retries from Goal, no-progress heuristic, or new message-withdrawal API. No SDK, ACP, or print support in v1.

Use small generic Rust/Lua interfaces for request-scoped attachment and attribution, lifecycle fences, and root-scoped status content. Policy (goal states, wording, transitions, evidence, counting rules, allowance, and recovery) stays in Lua. Rust owns synchronization and provenance, not Goal-specific state strings or a hardcoded tool name. Registration is not visibility: register the tool once, advertise it on new normal model requests to the active root only, and accept the schema/cache change at activation or deactivation. Provider retries reuse the original request unchanged.

In the same change, recreate the `init.lua` and `tests/spec.lua` paths required by `include_dir!` in `makima-lua/src/loader.rs` and `include_str!` in `makima-lua/tests/spec.rs` with fresh scaffolding so builds can proceed; do not keep old files as placeholders. Preserve the bundled `goal` identity and config enable switch. Use a fresh fixture for the harness self-test, then exercise the new plugin as its implementation lands.

### 1. Build the deterministic integration harness

Extend the scripted `Provider` fixtures around `makima-ui/src/agent/agent_loop.rs` and the managed host patterns in `makima-lua/tests/agent_handles.rs` and `tests/plugin_host.rs`. Build a narrow driver with a real TUI root actor, the bundled Lua plugin, actual command/queue routing, a temporary session state directory, and a recording provider at `Provider::stream_message`. Capture complete tool arrays, messages, request order, and actor turn IDs; drive a second root and a child when needed. Use channels/barriers for requests, tool responses, retry attempts, actor settlement, and persistence failures; no timing sleeps, external credentials, network, or real providers. If linking the full Lua host into UI tests would create a dependency cycle, put the combined driver in the workspace root integration target and expose only the necessary existing test seams via `test-util`. Verify first that a mid-stream normal submission is queued, appears only in the next recorded request, and can be distinguished from an unchanged retry. Use this harness for provider and lifecycle tests below, not a Lua mock of exposure.

### 2. Add the generic host primitives

- **Conditional registration and attachment.** Extend `makima.api.register_tool({ ..., enabled_by_default = false })` in `makima-lua/src/api/tool.rs`. Omission preserves existing registration behavior. Retain the static schema and route binding in turn-admitted definitions independently of exposure. Add idempotent `root:add_tool(ctx, name)` and `root:remove_tool(ctx, name)`, returning `(true, nil)` or `(nil, err)`. Only trusted code from the owning plugin may attach or detach its own opt-in tools on the pinned root. Detach does not unregister. Use the existing paired definitions and dispatch filters (`makima-agent/src/tools/mod.rs`, `agent/admission.rs`, `agent/run.rs`, `agent/tool_dispatch.rs`); attachment never bypasses mode, audience, binding, or permission checks. Keep definition order deterministic. No conditional tool is active on fresh roots, children, non-TUI roots, or after authority revocation. Do not use `describe`, mode switching, or global toggles.
- **Attribution and exact dispatch.** At construction of a *new* normal root model request in `agent/run.rs`, capture one immutable root/activation snapshot and carry it through `agent/streaming.rs` and the answering tool batch. Retries reuse that same request and snapshot; compaction remains tool-free. Only a request that actually advertises the tool can dispatch its conditional route, including nested dispatch paths; retain the existing audience, mode, permissions, and binding checks. Project the pinned turn ID and opaque activation identity from that invocation to its own handler (`makima-lua/src/api/util/ctx.rs`, `runtime.rs`; `CurrentManagedTurn` in `makima-agent/src/manager/types.rs`). Mint this claim authority only for a direct `CallOrigin::Model` dispatch to the exact advertised binding, scoped to that handler invocation. Strip it from nested, delegated, and named tool dispatch, including when they reuse a parent context. Do not infer provenance from `active_turn`, `latest_turn`, or current UI focus. A response from before activation, or from an activation subsequently replaced, paused, cleared, or revoked, cannot report for the current goal. Surface one request-exposure observation per root turn and counter scope (see phase 3), as well as an authoritative settlement observation for that turn; emit exposure when a logical request with the definition is submitted to the provider path, not by counting retries, tool calls, or `AgentIdle` events.
- **Ordering and fences.** Attachment and guarded idle admission each linearize with the relevant root state. After attachment succeeds, the next new normal model request sees the tool even within an existing turn; removal hides it at the same boundary. An ordinary `root:send(ctx, announcement, { when = "join" })` follows as a separate call. Do not add a tool option to `send`, reserve a queue entry during attachment, or require a shared cutoff. A request may see `goal` before the announcement reaches the model; `goal.status` must already return the committed objective. Join uses ordinary FIFO/admission rules, including fallback to a successor (`makima-agent/src/actor/mod.rs`, `actor/inbox.rs`). No in-flight request or retry changes. Route automatic continuation through the TUI quiescence check (`makima-ui/src/event_loop.rs`, existing background-wake gate), then guarded `when = "idle", after_turn = ...` admission with activation, config, and history validity. Already admitted user or child work wins; no `queue` or `join` retry. If Goal wins a simultaneous admission race, later submissions follow normal queue rules.
- **Settlement barrier.** A fast successor may already be admitted before Lua observes the previous turn's end. Keep a small host-held mailbox of ordered exposure/settlement facts for this opt-in mechanism. Publish the authoritative outcome in the actor retirement transition (`makima-agent/src/actor/mod.rs`), not in an asynchronous listener. Drain earlier facts through the controller before every relevant new request, guarded Goal send, and `/goal` read or mutation, including commands that race retirement. Use the retirement/command ordering point to decide whether a prior claim already settled or a command invalidated it first. An entering command must see a prior retired turn's count and result even if the Lua event has not yet run. This barrier is for conditional Goal eligibility, not ordinary turn admission: a failed, revoked, or unavailable controller clears its gate and lets normal requests proceed without the tool. Make delivery idempotent by exact turn ID and never hold actor locks while calling Lua or doing I/O; use a generation/revision check on re-entry. Do not depend on async autocmd order, or use the `AgentIdle.settled` presentation marker as a turn ID. Wire root rewind success at the history commit (`actor/history_edit.rs`, `makima-ui/src/event_loop.rs`), committed plan-mode changes, root cancellation/failure and plugin revocation into the eligibility fence so no next request or guarded send can use stale activation. On same-turn retries keep the prior request unchanged even after a fence; dispatch cannot submit a stale claim. Fork starts with a new session identity and no Goal activation.

### 3. Implement the Lua state machine, durable records, commands, and tool

- Use a versioned, validated per-session record under Makima's state directory, protected by existing live session ownership (`makima-storage/src/session_lock.rs`) and a per-session Lua serialization gate. Persist with bounded typed decoding and a trusted, session-scoped atomic sidecar writer in the host, not raw `makima.fs.atomic_write`. Validate the pinned session and plugin ownership, then hold the live session publication guard (`makima-storage/src/session_lock.rs`) at the atomic replacement boundary. Fence writes to the original ownership epoch throughout, including staged commit, clear, and recovery: a stale callback must not write under a successor's lease. Use a normalized host session identifier for the path, distinguish missing from unreadable/corrupt, and never deserialize live handles. Record a counter-scope ID (new after clear), a revision/activation ID (new on replacement and state transitions), immutable objective **per revision**, lifetime count and allowance ceiling (initially 10, extended by 10 on exhausted resume), state and stop reason, and enough exact turn/claim metadata to deduplicate and account in order. Use a durable clear tombstone to invalidate late callbacks. Keep bounded bookkeeping for in-flight/recent facts, not unbounded history. Existing sandbox/ownership checks still apply.
- Serialize command, tool, and actor inputs through one reducer/controller. Make the atomic sidecar replacement the durable command commit point, under the original session lease and ordered transition reservation. Reconcile earlier retirement facts before that commit; do not hold actor locks across storage I/O. A failure before replacement preserves the old record; a crash after it recovers the new record without replay, pausing it if active. No queue entry is reserved with this commit. Publish the committed revision before attaching the tool so `goal.status` can answer immediately. On replacement, fence the old request revision at the commit boundary even if the tool remains attached; repeating `add_tool` does not duplicate a definition or need to detach it first. On storage or attachment failure, report the error and keep exposure and autonomous admission disabled for the failed transition. An announcement send failure **after** attachment is different: report that the goal is active but its announcement was not queued; do not roll back attachment or retry the announcement automatically. Ordinary input remains usable.
- For graceful reload, close Goal admission and new exposure first, establish a cutoff in authoritative actor retirement order, and drain and durably reduce already-retired facts under the old writer's lease before revoking it. Preserve a confirmed terminal outcome from the drain; otherwise persist paused. Later retirement of an unfinished turn cannot rearm or confirm a claim across the cutoff. On reopen or abrupt restart recover the last committed record (any active state as paused), retain durably accounted counts and terminal statuses, ignore uncommitted staging, discard unresolved claims/admissions, and never replay announcements. An abrupt crash can lose process-only retirement facts that had not yet committed; it must not undo a committed command or permit automatic work. Report graceful drain/storage failure and leave the goal disabled. Rewind pauses the same record; fork with a new session ID has none.
- Use literal inline `makima.api.register_command` metadata with `arguments = { raw = true }`, TUI-only, parsing the full outer-trimmed argument as an objective unless it is exactly `pause`, `resume`, or `clear`. Bare `/goal` reports objective, state, current allowance progress, lifetime count, and stop reason without a model call. Reject all forms from a focused child; use the pinned command target rather than rereading focus after a yield. In plan mode reject set/replace and resume; inspect, pause, and clear still work. Entering plan mode pauses; leaving it does not reactivate.
- `/goal <objective>` sets or replaces and normally activates immediately, even mid-turn. Register the tool once at plugin load with `enabled_by_default = false`; set/replace and resume persist the objective and state, call `root:add_tool(ctx, "goal")`, and then separately call `root:send(ctx, announcement, { when = "join" })`. This queues a real user-role announcement via normal Join routing, e.g. `[system: goal set to …; use the goal tool]` or `[system: goal changed to …; use the goal tool]`; the prefix is presentation text, not a system role. Quote/delimit the objective as data. Queue it even when the allowance is exhausted, but then explain the cap and do not expose the tool or start automatic follow-ups. Setting/refining a paused, blocked, or completed goal activates if allowance remains, preserves the counter scope and count, and invalidates old reports. With no allowance left the replacement is capped until resume. Suppress automatic kickoff while the announcement send is pending. On success that announcement provides the initial work; on send failure report it without an immediate fallback send.
- `/goal pause` keeps the objective and allowance; `/goal clear` forgets the goal and resets both counts. Both call `root:remove_tool(ctx, "goal")` to hide the schema on the next new request; other stopping transitions detach it as well. Neither action cancels running work or removes a queued entry. `/goal resume` accepts paused, blocked, or capped goals, preserves remaining allowance (or grants the next ten if exhausted), activates and queues a fresh announcement even mid-turn. It refuses a completed goal. User cancellation pauses an active goal, even if the cancelled running turn had not yet seen the tool; terminal root failure and model/request-limit stop also pause. Failed tests and recoverable tool errors within a normally continuing turn do not pause it. Keep queued messages on pause/clear/replacement, even if their content is now obsolete; the handler's current identity checks are authoritative.
- Register one main-audience tool `goal`, with `op = status | complete | blocked`, and nonblank bounded `evidence` required for `complete` or `blocked`. The static description explains that status returns the objective, completion needs concrete verification, and blocking needs a concrete external dependency. `status` is read-only; claims only come from a root/provider invocation that was offered this exact live activation. Return an explicit provisional result. First valid claim for the current revision in a turn wins; reject subsequent conflicting claims; replacement invalidates the old claim and makes a claim for the new revision possible only after a new request sees it. Finalize only on the reporting turn's normal `finished` success; `failed`, `cancelled`, `max_tokens`, and `max_turns` never confirm it. Verify provenance and evidence shape, not task correctness.
- Count qualifying turns by `(counter scope, exact root turn ID)` once on settlement, even across replacement or mid-turn pause/resume. Ordinary messages and child-result wakeups qualify if the root was offered the tool; no child turn or wholly pre-activation root turn qualifies. Count exposed turns that fail or are cancelled; clear severs their old scope so they cannot charge a later goal. Process settlement in this order: account once, confirm a matching normal report if present, apply cancellation/failure/limit pause, otherwise cap when allowance is exhausted, otherwise keep active. A valid completion on turn 10 wins. A blocker on the last allowed turn stays blocked and gets another ten only on explicit resume. If the same turn saw two revisions that share a counter, charge once. Retain the lifetime count across extensions; use the current allowance's `0..10` in the badge.
- On idle reconcile the latest exact retained turn and any outstanding facts before submitting one automatic continuation for a still-active revision. Guard by latest settled turn, live activation, and committed policy/history. Never send from a blocked, capped, paused, cleared, uncertain, or complete state. Busy/stale is not a failure or a pause; wait for a legitimate new boundary, never spin. Root work may proceed while children work; ordinary delivery keeps its normal priority/behavior and may instead wake the root. Use stable bounded continuation text with the current objective. No automatic Goal-layer retries after a terminal turn failure.

## Acceptance Criteria

- **AC.1 — Harness.** The test driver can hold a real streamed request, enqueue normal input, observe it only in the next logical provider request, and distinguish a retry from a new request, deterministically.
- **AC.2 — Command and queue.** Set, replace, and resume work mid-turn with real queued announcements, preserving normal queue ordering and the in-flight request. A request between `add_tool` and `send` sees the tool and can read the objective with `status` before the announcement arrives. Join fallback does not move text ahead of other input. A send failure after attachment leaves the goal active, reports that the announcement was not queued, and does not retry it. Idle set starts work once. Pausing, clearing, or replacing leaves preexisting announcements and unrelated input alone. Bare status has no provider call, and command routing refuses a focused child and unsupported frontends.
- **AC.3 — Request visibility.** Actual provider requests show the registered `goal` schema only for the active TUI root, including the next new request in an existing turn. Advertisement order/schema are stable within the same tool environment; other roots, children, disabled plugins, disallowed modes, and inactive requests never advertise it. Retries have the original payload.
- **AC.4 — Claim integrity.** `status` reads the objective; first valid complete/blocked claim is provisional, only the exact normally finished root turn commits it, and stale or never-advertised requests and delegated paths cannot act on a new goal. Ordinary finish alone doesn't complete it. Nested dispatch cannot submit a claim even while the parent request was offered the tool.
- **AC.5 — Counting and allowance.** Count once per exposed root turn, including ordinary prompt and delivery turns and exposed failures/cancellations; exclude child and unexposed turns. Preserve progress on replacement, discard on clear, and never expose the tool on turn 11 of an allowance, even if a user successor is queued before Lua event delivery. Normal turn-10 completion wins; without a claim the cap independently hides the tool on turn 11. Status, refinement, and resume see turn 10's authoritative retirement even before the asynchronous event runs. Exhausted resume grants ten more without losing lifetime count.
- **AC.6 — Continuation scheduling.** Idle continuation neither steals already admitted user work nor inserts a hidden queued follow-up. Busy/stale attempts don't spin; independent events don't duplicate work. Running children are not a gate and child delivery can win the wakeup. Normal prompts neither pause nor reorder because of Goal. Actor-idle TUI recovery text is preserved and defers Goal.
- **AC.7 — Pause and resume.** Explicit pause, user cancel, root failure, model/request limit, and plan entry disarm; entering/exiting plan never schedules Goal work. Nonterminal tool failures do not pause. Resume matches allowance and terminal-state rules; replacement at cap still queues an announcement without rearming.
- **AC.8 — Recovery.** Durable records survive reopen, reload, and rewind without automatic restart; fork does not inherit. In-flight callbacks cannot rearm across rewind/clear/revoke. Failed reads/writes, interrupted admission, and corrupt records fail closed while normal input still works. A callback from a lost lease cannot replace a record owned by a successor. Before/after durable command commit crashes recover the old/new objective and the appropriate count and terminal/paused state, without replay. Graceful reload after retirement but before Lua event delivery preserves the settled count and confirmed outcome.
- **AC.9 — UI.** In the focused root view the gold badge shows the current active qualifying turn, including initial `0/10`. It is absent when inactive and does not leak into another root or child on a focus switch, or clobber another plugin's status.
- **AC.10 — Packaging and docs.** The default-enabled bundled command, optional disable, and TUI-only metadata are testable, and generated docs match shipped commands and Lua APIs with no obsolete checker options.

## Risks, Blockers, and Required Decisions

- **Async ordering:** Lua callbacks can arrive out of order and a queued successor may run immediately. Test the request/settlement fence rather than relying on callback order or a status poll. Never wait for Lua while holding actor or Lua VM locks; build the harness first to exercise forced interleavings.
- **Stale queue text:** Leaving queued announcements alone after pause/clear/replacement is intentional. The request-bound identity and current gate, not bracketed text in history, authorize Goal operations. No message-withdrawal mechanism is in scope.
- **Durability:** Storage and actor admission cannot commit atomically. Commit the objective before attachment and use ordinary queueing separately. Fail closed on storage errors, report announcement failures without rollback, drain retired facts at graceful reload, and do not replay announcements or ambiguous work. Protect persisted goals from cross-session and cross-process writes.
- **Permissions/cache:** Conditional activation intersects existing filters and never grants mode or permission authority. Unrelated MCP/tool changes may still change the provider prefix; Goal adds no per-objective schema churn. Retry reuse must not refresh a payload after the logical request is built.
- **Scope:** This is a replacement, not an incremental port of the checker draft. No known product decision blocks implementation after operator approval; the provider/actor harness and scoped host primitives are implementation work in this plan, not deferred prerequisites.
