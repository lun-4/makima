## Goal

Implement typed positional command arguments with one quote-aware parser shared by execution and autocomplete. Rust and Lua commands receive type-specific default suggestions and per-argument customization; builtin `/cd` uses an ordinary optional Directory argument, with no command-name or producer-specific completion logic.

## Implementation Summary

This replaces the earlier whole-remainder completion-hint plan. Add typed argument contracts and parsing to `maki-commands`; extend registry completion sessions to compose incremental defaults and custom providers; expose schemas and typed values in Lua; integrate filesystem suggestions into the command palette rather than maintaining a second command popup.

Use a test-only `/copy <source:file> <destination:directory> [policy:enum]` command, with `skip` and `overwrite` policies. Its Lua handler records inputs without copying anything. It proves mixed argument types, spaces/quotes, later-argument replacement, and destination-provider customization independently of `/cd`.

First-version types: String, Integer, Enum, File, Directory. Support required, optional, and final variadic positional arguments. No named flags, subcommands, shell evaluation, arbitrary custom types, or filesystem-existence policies in this change. File/Directory indicate path intent and default discovery; handlers validate existence if needed. Legacy `nargs`, raw Markdown/MCP commands and command-wide providers remain compatible. Only `/cd` must migrate among existing builtins; model/theme/btw can remain legacy.

Important behavior change accepted by adopting a real typed parser: `/cd my project` is two arguments and fails; `/cd "my project"` is one argument and works. Completion quotes inserted paths automatically. Do not retain an implicit last-argument-rest or `/cd` exception.

## Implementation Plan

### 1. Core schema, validation, and invocation values

Touch `maki-commands/src/{spec,registry,dispatch,lib}.rs` and an essential new `arguments.rs` module for the parser/schema helpers. Keep filesystem and Lua dependencies out of this crate.

- Replace `CommandSpec.arguments: ArgumentArity` with `CommandArguments::{Legacy(ArgumentArity), Positional(Arc<[PositionalArgument]>)}`. Each positional descriptor contains `name`, `kind`, `optional`, `variadic`, and a completion policy enum `Default | Disabled | Replace | Extend`. Keep callback objects separate from comparable metadata in registration.
- Types are `String`, `Integer`, `Enum(Arc<[Arc<str>]>), File, Directory`. Validate unique nonempty argument names, valid enum choices (nonempty, distinct, nonempty strings), required-before-optional order, and variadic-only-last. Required variadic consumes one or more; optional variadic consumes zero or more. Reject contradictory/provider-less Replace/Extend and providers attached to Default/Disabled, and typed schemas combined with a legacy command-wide provider.
- Add ordered per-argument providers to `Registration`, indexed by descriptor, with explicit absent entries. Keep existing `Registration.completion` for legacy commands. Validate provider vector length and policy consistency atomically in `validate_registrations` (`registry.rs:644`). Add descriptive `RegistrationError` variants. Failed batch replacement leaves the previous registration usable.
- Derive typed min/max bounds and generated usage hints from the schema rather than storing duplicate counts. Preserve explicit documentation hints. Builtin definitions need a const-friendly static schema representation converted by `BuiltinDefinition::spec`; extend the existing macro with a typed form. Do not switch on names or builtin actions to construct schemas.
- Integer is signed decimal, optionally prefixed by `+` or `-`, with no separators or alternate bases. Use checked i64 parsing, then require the portable exact-number range `[-9007199254740991, 9007199254740991]` for this initial type in both Rust and Lua. This avoids Luau's floating-number rounding and avoids a value whose Lua representation changes between number and string. Use named constants and document this range.
- Enum execution is exact and case-sensitive; fuzzy suggestions do not relax validation. Strings retain decoded text, including empty quoted strings. File/Directory are decoded, nonempty, NUL-free path spellings; they are not canonicalized, expanded or checked for existence during type validation. Rust values carry path intent with `PathBuf`; Lua values carry the same decoded spelling as a string. Original command arguments remain available separately.
- Add `CommandInvocation.parsed_arguments: Option<ParsedArguments>` holding ordered decoded tokens and typed values, with schema-aware named accessors and variadic slices. Avoid duplicating a name/value map in Rust. Legacy invocations have None.
- At `dispatch.rs:138`, after existing target/winner/capability validation and before calling behavior, parse and validate typed arguments or retain the legacy whitespace-count path. Errors include argument name/index, expected type and byte span, and prevent handler execution. Reuse this validation entry point for alternate Lua invocation paths.
- Update all workspace constructors and consumers of `spec.arguments` (including UI filtering, docs, ACP, print/SDK, MCP and test fixtures). Legacy producers wrap their existing arity; do not migrate Markdown substitution, MCP remainder binding or natural-language `/btw` to a token parser.

### 2. Quote-aware lexer and insertion encoder

Implement one pure lexer in `arguments.rs`, with strict execution and tolerant completion modes. It receives the argument remainder, not a command name, and returns decoded tokens with source byte ranges. Slash spelling extraction remains generic and uses existing `ParsedInput` parsing. Completion translates between remainder-relative spans and first-line input coordinates explicitly.

Grammar:

- Unicode whitespace separates tokens outside quotes. Single and double quotes group text. Adjacent quoted/unquoted fragments concatenate. Empty quotes form an empty argument.
- Backslashes are literal outside quotes and inside single quotes, preserving ordinary Windows paths. Inside double quotes, only `\"` and `\\` decode to an escaped quote/backslash; a backslash before another character remains literal. No unquoted backslash-space escape, variable/command substitution, glob expansion, or shell operators.
- Strict parsing rejects unterminated quotes with useful spans; tolerant parsing permits an unfinished active token. Both use exactly the same tokenization rules. Newlines are whitespace outside quotes and literal inside quotes for core execution; TUI autocomplete remains limited to the first command line and never rewrites later lines.
- Completion context includes active token index, mapped descriptor index (last descriptor repeats for variadic arguments), raw whole-token range, decoded full value, decoded prefix through the cursor, quote state and successfully validated preceding values. Missing required preceding tokens do not block completion of the current slot; invalid preceding values are absent from the context's typed values and dispatch still fails normally. Cursor in inter-token whitespace denotes an empty slot before the following token; at token end immediately before whitespace it belongs to that token. Invalid byte/UTF-8 offsets return no context.
- Central encoder receives a semantic candidate value and returns a `CompletionEdit` with replacement range, encoded text and cursor. Replace the entire active token and preserve all other text. Preserve an existing single/double quote style when it can express the value; otherwise use double quotes and escape backslashes/quotes. Quote any value containing whitespace or quote delimiters; encode an empty value as `""`. Never ask a provider to produce quotes.
- Accepted edits end with balanced quotes and position the cursor after the token. Directory descent also inserts balanced syntax but positions the cursor inside a closing quote so continued typing/Tab extends the same path. The parser must recognize cursor positions on either side of a closing quote consistently. Do not append a space on Enter acceptance; the next explicit space moves to the next slot.
- Add exhaustive table-driven lexer/cursor/encoder tests, including single/double quotes, mixed fragments, Windows drive/UNC paths, trailing backslashes, literal `@`/colon, empty values, Unicode, incomplete quotes, middle-of-token replacement and surrounding arguments. Test `strict_parse(encode(value)) == value` over a generated matrix using existing test dependencies, not a new fuzzing dependency.

### 3. Unified typed completion contracts and sessions

Extend `maki-commands/src/completion.rs` and registry completion opening; retain the existing one-shot trait as the adapter path for legacy providers.

- Typed requests take raw arguments and byte cursor; derive slot/type/query/preceding values centrally using the shared parser. Legacy requests retain their existing token/query interpretation. `CompletionContext` gains optional typed argument metadata and preceding typed values without changing existing legacy fields.
- Extend candidate metadata with semantic insertion value, match text separate from display label, display kind, and explicit navigation (`Terminal` or `Directory`). For typed providers `insertion` means decoded value; legacy insertion remains literal. Derive encoding from the session argument contract, not provider-supplied shell syntax. Do not infer navigation from labels/kind strings.
- Add a typed session-opening entry point taking the active descriptor index and an optional frontend default provider. Registry selects the registered per-argument custom provider and composes it according to policy. Enum defaults live in the neutral core; File/Directory defaults are supplied by the TUI. String/Integer defaults are empty. Other frontends can inject filesystem defaults later; no ACP extension is promised.
- Add an overridable incremental provider entry point using a thread-safe snapshot sink, with a default adapter that calls existing `complete` once. Snapshots replace the provider's prior candidate list and carry pending/finished status. Use callback-based sinks in the core so no executor/channel dependency is needed there. The UI uses an existing workspace channel/coalescing primitive to retain only the newest pending snapshot. Keep an explicit terminal/error signal so a coalesced snapshot cannot lose completion status.
- Composition keeps latest bounded default/custom snapshots, deduplicates by decoded insertion value, and gives custom duplicates precedence (including navigation/description). Preserve deterministic order before existing fuzzy ranking; cap materialized combined results at the existing menu cap, allowing custom duplicates to replace defaults before capping. Extend retains defaults on custom failure; Replace failure has no suggestions. Report provider errors through existing logging/flash mechanisms without stale rows.
- Track candidate provenance internally. Highlight/accept hooks go only to the provider that produced the selected candidate; selecting a default candidate does not invoke a custom preview hook. Publication completion, request cancellation, and session lifecycle termination are separate states. Session cancellation terminates each participating provider once; terminal acceptance accepts the winning provider and cancels every nonwinning provider whose lifecycle has not terminated, even if it already published its final snapshot. A final snapshot never implies that preview state has been released. Track exactly-once lifecycle termination separately from whether a provider still has work in flight. Directory Advance is a nonterminal requery, not Accept. Custom typed providers may explicitly mark a directory candidate as navigable.
- Session identity includes registration CommandId, invoked spelling, target, active token index/descriptor, mode and cwd context. Changing query allocates a request generation synchronously before returning/spawning its future, fixing the existing first-poll ordering hole at `completion.rs:208`. Argument/target/command/context changes cancel and reopen; query changes supersede requests without discarding reusable discovery.
- Assign each published composite replacement snapshot a monotonic revision within its request and stamp opaque candidates with that revision. Atomically advance the current revision when replacing the candidate set. Reject superseded candidates before highlight, Advance and Accept even if the query/request/input is unchanged. When receiving a new snapshot the UI discards old candidate handles, preserves selection by semantic value only if present, and binds selection to the fresh candidate and provenance. A removed value resets selection; changed navigation or custom-over-default provenance is never inherited from the old row. Validate current winner/target, request generation, snapshot revision, and current input/cursor revision before returning candidates and before applying edits. Lifecycle/accept errors must prevent insertion rather than be ignored. Use registry opaque candidates for filesystem defaults too; do not leave directory completion outside cancellation/stale checks.

### 4. Reuse filesystem discovery behind the unified palette

Touch `maki-ui/src/components/{file_completion,file_picker,arg_completion,command}.rs`, with an essential new filesystem discovery module within `maki-ui` if extraction requires it. No new crate.

- Extract resolver, explicit-path listing, project walker/nucleo state and bounded materialization out of file menu presentation. Reference completion and typed File/Directory providers reuse this service. Preserve ignore rules, root exclusion for typed paths, symlinks, smart matching, namespace-preserving `./`, `../`, absolute and `~/` spellings, and filtering before materialization caps. File default includes files plus navigable directories; Directory default includes directories only.
- Keep project walk/index alive for a provider session/cwd and reparse queries incrementally. Publish coalesced replacement snapshots while walking rather than waiting for the complete tree. Explicit directory reads run off the UI thread. Cancellation/drop stops walkers and pending publications. Preserve the existing 640-item materialization bound; do not claim the full walker index is bounded. Reference refresh must retain its existing bounded scan, not scan every path for a new typed filter.
- Construct TUI default providers in `arg_completion.rs` and inject them at palette session opening. Pass the current session cwd from App as immutable completion-context data, just as the existing file menu receives it. Do not introduce a second mutable cwd store or query process cwd. App already owns authoritative TUI cwd and target switching. Pass home context through the existing injected home/resolver seam.
- Discovery uses decoded path queries. Path spellings in handler values remain unexpanded. Provide a pure shared `resolve_path(cwd, home, spelling)` helper in `maki-commands/src/arguments.rs`, exported for both maki-agent and maki-ui, with a `PathResolutionError` covering invalid empty/NUL spelling, unsupported home-user syntax and unavailable home. It uses only `std::path` joins and checks, with no filesystem I/O, environment lookup or UI dependency; callers supply cwd/home. Use it for handlers/builtin execution and discovery-parent resolution: absolute paths unchanged, relative paths joined to cwd, only `~` or `~/` (and native Windows equivalent) expanded, unsupported `~user`/missing home reported explicitly. Do not canonicalize or collapse symlink-sensitive `..`. The reference adapter preserves its old namespace/parser behavior rather than inheriting command quoting.
- Use CommandPalette as the sole command-argument controller for defaults/custom/merged results. Remove `is_builtin_cd`, the `/cd` prefix parser, App's dedicated directory command menu branch, and duplicate directory render ownership. `FileCompletionMenu` remains the `@` reference adapter, not a second command argument controller.
- Route typed File/Directory suggestions and `@` references through the same full-input-width grid renderer and `CompletionGridState` implementation. Share column layout, selection, viewport scrolling, and all four arrow-key handlers. Up/Down move vertically; Left/Right move horizontally and do not move the prompt cursor while the path grid owns input. Both adapters use the same boundary and incomplete-row behavior. Non-path command suggestions retain their linear list.
- Keep data and insertion adapters separate from the shared grid. Directory filesystem defaults filter out files before materialization; File defaults include files and navigable directories. Do not filter custom Directory candidates by navigation metadata: a terminal candidate can still represent a directory. Reference acceptance replaces an `@` token; typed acceptance validates opaque candidates and applies quote-aware argument edits.
- During directory descent, retain the committed parent rows and grid until child results arrive. Start a pending request without clearing the visible argument state. Retained rows cannot be accepted or advanced: Tab and Enter are consumed during this transition. Replace them with current child candidates when available, including an empty final result. This prevents an empty-panel flash without claiming to reduce filesystem latency.
- Resolve the exact typed command spelling through `registry.resolve_for`, including aliases/case variants and collision winners. Fuzzy slash rows do not activate a nearby command's schema. After an exact typed name and separator, display/dispatch that command even with currently incomplete/invalid arguments; strict validation errors must not turn it into ordinary chat. Prefix command discovery remains available before committing to an exact command.
- Replace palette's global whitespace-count filtering with schema-aware context handling. Typed commands are not hidden for quoted spaces, missing required slots or incomplete quotes. Keep legacy matching/arity behavior unchanged.
- Enter with a terminal candidate accepts only; subsequent Enter executes. Tab on terminal candidates accepts only; Tab on directories descends. In a File slot both Enter and Tab on a directory descend, because it is a navigation candidate. In a Directory slot Enter accepts and Tab descends. Empty results consume Tab and let Enter dispatch/produce parser errors. Pending directory-descent refreshes with retained rows consume both keys until current results arrive. Escape closes suggestions without changing input.
- Typed argument ownership suppresses slash rows and reference suggestions inside typed slots even after dismissal or acceptance. Replace whole-input acceptance suppression with active-slot/input-revision suppression so moving to the next argument opens its defaults; ticks/cwd changes alone do not reopen dismissed/accepted completion.
- Retain input synchronization for typing, Ctrl/cursor movement, paste, mouse, command-name Tab, newline, mode/cwd changes and target switches. Recheck owner identity on key handling and ticks, and suppress stale rendered rows before the next tick. Active cwd changes reopen with fresh context; dismissed sessions stay dismissed. Later lines are untouched and do not activate command completion.

### 5. Lua schema and per-argument adapters

Touch `maki-lua/src/api/{tool,completion}.rs`, `api/util/command.rs`, `runtime.rs`, and existing host tests. Follow `maki-lua/src/api/AGENTS.md` conventions.

Public schema example:

```lua
maki.command.register({
    name = "copy",
    description = "Test typed path arguments",
    tui_only = false,
    arguments = {
        { name = "source", type = "file" },
        { name = "destination", type = "directory" },
        { name = "policy", type = "enum", choices = { "skip", "overwrite" }, optional = true },
    },
    handler = function(opts)
        record(opts.values)
    end,
})
```

- `arguments` is a dense positional array. Reject any simultaneous non-nil `nargs` or command-wide `completion`, including `nargs = 0`. Recognize exactly string/integer/enum/file/directory types and boolean optional/variadic fields; validate unknown type/policy values, malformed arrays, duplicate names and enum choices.
- Per-argument completion: omitted uses defaults; `false` disables; `{ items = ... }` or `{ get_items = function(ctx) ... end }` replaces; `mode = "replace"` is explicit replacement; `mode = "extend"` adds defaults. Require exactly one of items/get_items. Reuse existing item label/insertion/description shape with typed insertion semantics; add explicit `navigation = "directory"` when desired. Lifecycle hooks use the same names as legacy hooks and the provenance rules above.
- `ctx` retains existing fields and adds argument descriptor metadata and `values` for valid preceding arguments. `ctx.index` remains zero-based; variadic values are arrays. Arguments named `values`, `args` etc. are safe because values live in their own table.
- For typed handlers, `opts.args` retains the existing outer-trimmed original source with quotes; `opts.fargs` is the decoded token array; `opts.values` is a name-keyed table of strings/path spellings, safe integer numbers, and variadic arrays. Absent optional scalars are nil; an absent optional variadic is an empty array. Legacy commands keep current args/fargs semantics and do not gain a misleading typed table.
- Factor option construction shared by `Request::RunCommand` and `Request::ExecuteCommand` (`runtime.rs:3507,3542`). Alternate typed invocation must validate using the same core parser before scheduling a handler, return failure through its existing reply channel (extend that internal reply to Result if necessary), and never downgrade to legacy whitespace parsing. Registry invocation uses already-validated values rather than reparsing independently.
- Store per-argument callback keys separately from portable schema, indexed by descriptor. Parse and validate the full candidate registration before mutation, clean staged keys on failure, and publish atomically. Bind adapters/hooks to immutable registration generations, not a fresh name lookup: retiring an old generation must not call new hooks or handlers. Retain old callback keys until old sessions finish cancellation, then release exactly once on the Lua thread. Reuse existing retired-entry machinery with generation-aware lookup.

## Risks, Blockers, and Required Decisions

- No unresolved product blocker: the user approved typed multi-argument schemas with quoting and customizable type defaults. This plan makes the corresponding `/cd` whitespace compatibility change explicit and does not preserve it with a special case.
- Quoting is intentionally not a full shell grammar. Unquoted backslashes remain literal for Windows; users quote spaces. Path spellings are not expanded in handler values. Existence validation is left to handlers, allowing nonexistent destinations.
- The Integer type deliberately uses the exact portable Luau number range, even in Rust, to avoid silent rounding or a number/string union. A larger-integer type is out of scope.
- Incremental completion and composition add state; central session ownership, coalesced snapshots, provenance and explicit finish signals are required, not optional optimizations. The walker index remains unbounded as before; only materialized results/publications are capped.
- Completion defaults for filesystem types are supplied by the TUI adapter. Core typed parsing/validation and enum completion are frontend-neutral; ACP currently has no standard typed-completion advertisement and its wire schema remains unchanged.
- Registration/key lifetime bugs can misroute old hooks to new plugins. Generation-bound adapters and atomic staged Lua keys must be implemented and tested before UI rollout.
- Legacy nargs/raw APIs remain intentionally different from opted-in typed schemas. Document this boundary clearly and do not silently migrate natural-language commands.
- Native Windows filesystem behavior can only be fully verified on Windows CI. Portable quote/UNC/drive spelling tests and platform-gated filesystem tests are included; record which platform runs actually occurred.
