## Goal

Revise PR #146 so managed agents own configuration and serialize changes with admission through one coherent operation path. Eliminate stale setter snapshots, coordinator/actor circular waits, late configuration commits after cancellation, mixed admission snapshots, and managed Lua execution that disagrees with actor configuration.

## Implementation Summary

Keep the persistent actor, execution queue, manager graph, cancellation identities, completion outcomes, and pinned tool-binding work. Redesign configuration sequencing, not the whole agent system. Grounding: current PR head f0af57e5830d390d5e561495b2dac59b0d07e2a7; #24 tracking comment https://github.com/lun-4/makima/issues/24#issuecomment-5856345383 and #27 establish actor ownership. #123/#130 need composable setters; #41/#148 need a future single state source, not a durable state log in this revision.

Use typed configuration changes applied to the preceding committed configuration. A single actor-side FIFO contains configuration changes and unprepared admissions; the existing execution queue remains separate. Prepare providers without mutating live state. Commit in the actor, then project committed state to UI, coordinator, provider slots, and existing storage. Managed Lua turns execute their admitted configuration.

Operator decision: setters succeed at actor commit. Persistence is asynchronous. Save failure leaves the committed configuration active, emits an explicit applied-but-not-saved warning, and retains the latest committed snapshot for retry. Preparation/validation failure leaves configuration unchanged. No configuration rollback on persistence failure; no admissions blocked on disk I/O. A crash before saving can lose the latest change, and documentation must state this.

Touch points: maki-agent/src/actor/{mod,types,queue,runner,tests}.rs; manager/{mod,types,tests}.rs; agent/run.rs and tool_dispatch.rs; session_coordinator.rs and session_options.rs; maki-ui/src/event_loop.rs, agent/{mod,agent_loop}.rs, storage_writer.rs; maki-lua/src/api/{agent,model,session,mode}.rs and managed-session tests. Preserve ACP/headless legacy frontend support without migrating their execution loops to the manager (PR 9).

Non-goals: new Lua Agent API, full frontend migration, graph/state-log persistence, full rewind restore, guest mode ownership, generic capability/effect lattice, host-effect sandbox, anchored filesystem writes. Remove the bundled-provenance restrictive allowlist added by this PR, as the #24 scope explicitly defers it. Preserve existing generic mode tool selection, native write-target checks, MCP restrictive-mode denial, permissions, graph limits, and model allow-policy.

## Implementation Plan

### 1. Replace competing configuration APIs with typed changes

Add a small actor configuration module if it consolidates the logic rather than merely moving it. Retain EffectiveAgentConfig as the full committed value (settings/provider/model, selected mode and resolved ModeDef). Require a resolved definition for selected custom modes; reject missing definitions visibly. Resolve mode selection once, before submitting its typed change. Do not consult the mode registry again to execute an admitted configuration.

Represent updates as explicit field changes, not full snapshots copied by adapters. Support an atomic model/options patch (prepared provider/model replacement plus optional thinking/fast/workflow fields), mode selection with its resolved definition, and boolean toggles evaluated against the predecessor configuration. Unspecified fields remain unchanged. A combined model/options call commits once. Apply capability normalization using RequestOptions::clamped in the shared reducer, and reject explicitly unsupported requests consistently with current public errors. Provider refresh and model discovery use conditional changes with expected provider identity/model spec so obsolete refresh results cannot overwrite a later selection.

Provider preparation may finish out of order but returns only a prepared provider/model or an error. It must not install ProviderSlot, mutate coordinator options, persist a candidate, or publish UI state. Resolve a typed prepared change into its reserved FIFO position. The reducer applies it to the then-current predecessor config, not the state at reservation or preparation completion. Keep exactly one public reservation/update mechanism. Migrate production callers of update_policy, set_effective_config, resolve(RunSettings), resolve_config(full stale config), and duplicate reserve aliases; keep initialization as a separate construction-only operation. Avoid compatibility aliases with divergent semantics. Use one equality/no-op rule for every update; unchanged config does not increment generation or split batching. Preserve resolved ModeDef on settings-only updates.

Cancellation and timeout: an unresolved preparation ticket may be cancelled/expired atomically. Late preparation results cannot commit or publish projections after cancellation. If commit already won, report its committed result rather than cancellation. Turn cancel-all preserves setters; actor close/shutdown rejects all uncommitted changes and settles their waiters. Dropping a wait future alone does not imply cancellation of an already committed operation. Keep errors typed, not recognized by matching timeout strings.

### 2. Linearize admission with configuration in one FIFO

Replace ActorState.pending_policy plus deferred_admissions/after indices with one typed FIFO of Config, Turn, Root, Compact entries. Keep ActorQueue as the queue of fully materialized execution work. Reserve/append each operation synchronously under the actor state lock. Keep admit_turn and rush synchronous acceptance APIs; a returned turn ticket may await materialization as today.

Use one driver routine with logical ownership identified by the preparing entry's unique identity, not an unqualified boolean that an obsolete completion can clear. At the head, a pending config blocks only subsequent admissions/config commits, not active execution. A ready config is reduced/validated/committed under the state lock. A work entry captures current config/generation and remains represented as the head while preparation runs outside the state lock. Execute synchronous AdmissionPreparation on the blocking pool (smol::unblock), never inline in admit_turn/rush or on an ordinary executor thread that would perform blocking filesystem reads. The synchronous APIs acknowledge acceptance; setup failures after acceptance terminalize the ticket or report the root setup error through the existing path.

Later config entries cannot overtake a still-live preparing entry. Removing/cancelling that entry immediately releases its logical driver ownership and wakes the next eligible FIFO entry without waiting for the blocking callback to return. Blocking work may finish physically later; its completion must match the current entry identity before materialization or driver-state mutation. A stale completion cannot clear a successor's ownership, enqueue work, publish config, or duplicate an outcome. Close/shutdown similarly invalidate outstanding preparation identities. Keep abandoned work limited to the already-started preparation; do not retry it or create a second preparation for the same entry. Reacquire state on completion, verify identity and lifecycle, then materialize work with the same captured config and snapshot. One helper finalizes ordinary turns and roots; compaction uses the same ordering without unnecessary prompt preparation. Controls that do not carry policy retain existing execution semantics.

AdmissionPreparation should receive the captured configuration or its resolved mode explicitly, rather than re-resolving mode from a mutable registry. Pin tool identities, cwd/instructions, MCP prompt identity, and prompt-slot request at this admission boundary. Retain the current asynchronous resolved-prompt receiver consumed during execution; do not hold state locks while reading instructions or invoking preparation, and do not re-run preparation to repair a raced config. Async prompt resolution must use the captured dependency/request and fail visibly for missing dependencies. Drop cancelled work receivers safely.

Adapt clear/remove/remove_visible_at/cancel_turn/cancel_correlation/cancel_existing to raw FIFO work and materialized work. Config entries are invisible in queue counts and are not removed by turn cancellation. Every accepted turn terminalizes exactly once, including removal during preparation. Roots retain correlation precancellation semantics. Queue projection ordering is materialized work followed by pending FIFO work, omitting config operations. Preserve generation-based batching, None batch-key exclusion, compaction barriers, and existing cancellation-generation/manager waiter registration rules.

### 3. Publish actor commits; remove the coordinator configuration transaction

Return/publish each committed config with actor identity, generation, and authoritative full value. Commit publication must not await UI, coordinator, or storage. Use an ordered per-runtime delivery path registered during runtime construction; do not depend on a setter caller continuing to await its result to publish state. Success replies contain the committed value, not a subsequent read from a mutable slot.

For managed TUI roots, replace ModelAdopter's install-during-prepare behavior with side-effect-free provider construction. Remove policy_from_coordinator, sync_actor_policy, finish_reserved_session_op reconciliation, PreparePolicyOption's external decision handshake, and repeated prepare/resolve/wait/commit-or-abort blocks from the managed configuration path. SessionCoordinator read options/model become projections for actor-owned fields. Model/fast/thinking/workflow setter requests from TUI, Lua session options, and Lua model API route to the same actor change entry point. Preserve public Lua pair/error shapes. Non-actor settings such as YOLO and plugin options retain their existing owner and immediate permission behavior; do not add actor generations for them.

Coordinator projection application must be a short operation, merge only actor-owned fields into current session options, preserve plugin/YOLO values and catalog/version checks, and enqueue persistence without awaiting an external actor-dependent decision. Reads immediately following a successful managed setter must consult the actor result/config rather than stale projections. The UI may process commit events later, but monotonically projects full committed state and never requested partial payloads.

Directory and history changes remain lease-ordered session operations, not configuration setter reservations. Remove /cd's actor config ticket. A submitted directory change applies after the active lease; do not report cancellation simply because a reply waiter timed out while the coordinator can still execute it. Keep the existing accepted/deferred UI behavior and wait for the real completion; close/retirement must resolve waiting requests explicitly. Config changes and YOLO continue while a directory change waits for a lease. Admission pins whichever cwd is actually committed at its boundary. Do not redesign history timeout or full session transitions beyond preventing config coupling and stale completions.

Tag all asynchronous setter/session completion events that can update App state with the originating actor/runtime identity, not just session ID. Discard completions from a retired runtime and generations older than the last projected config. Rewind/reload retaining a session ID must not accept old mode/thinking/model payloads. Use existing actor identity where sufficient rather than inventing a second identity counter. Provider slots are execution-independent compatibility projections; active turns retain admitted provider instances even after refresh.

### 4. Make persistence an ordered, retryable projection

Adapt SessionCheckpoint/StorageWriter integration only as needed to persist committed model/options/mode/plan projection through the existing format. Configuration-only saves carry history=None and must not overwrite a lease holder's current transcript. Include enough runtime/config identity in the in-memory projection protocol to reject obsolete saves before enqueue and prevent older completions from clearing newer dirty state. Preserve coordinator CheckpointVersion/epoch and storage generation ordering instead of replacing them with an unrelated ordering scheme.

Update read projections immediately; perform checkpoint waits in a separate observer that reports completion without occupying the coordinator receive loop. A failed save must retain the latest committed actor snapshot in the retryable ordinary storage path. Current failed coordinator candidates are discarded (storage_writer.rs), so do not reuse that behavior for committed config. Emit a visible, generation-associated 'configuration applied but not saved' warning; avoid duplicate warnings from coalesced saves. A successful retry of the latest state clears its pending-save indication. Older acknowledgements/failures never regress active config or replace the latest retry snapshot. Persist mode/plan metadata from the same committed projection where the current session format supports it, without adding PR 6's per-turn state log.

Test existing save coalescing, history=None merging, and runtime replacement ordering. Limit any storage fixes to what is required to make these config projections safe; the separate general writer/history race issue #149 remains outside this revision unless directly necessary for the new tests.

Lua already resolves model_spec/inherit_provider/options before constructing AgentParams; feed that resolved value into the child actor at creation, before it accepts turns. Preserve model allow-policy validation, live-parent capability checks, graph limits, nesting limits, and cancellation registration.

Remove the PR-added exact parent provider/model equality ceiling and related PolicyCeiling plumbing/tests where they enforce the deferred child-policy system. It conflicts with existing task model selection and is not a generic narrowing rule. Do not replace it with another capability lattice. Preserve current custom/plan mode inheritance and tool filtering, without claiming comprehensive child-effect containment.

LuaActorBackend uses context.policy for provider/model/options/mode on every managed turn. Stable dependencies may remain in state.params, but cannot override turn configuration. Missing managed policy fails visibly. Unmanaged legacy sessions retain their explicit initialization path. Nested children inherit the actual executing parent's admitted configuration unless an allowed explicit model is selected. Avoid redundant clones of settings in input/backend state becoming execution authorities.

Keep headless/ACP/print adapters operational. Their full manager migration remains PR 9. If shared coordinator API changes affect them, retain an explicitly scoped legacy owner/adapter rather than routing managed actors through legacy adoption. Do not create a second new FIFO implementation for ACP. Preserve early-input queuing, queued settings/prompt pinning, provider refresh, session option error shapes, and ACP completion/lease behavior. Document this migration boundary accurately.

## Risks, Blockers, and Required Decisions

- Resolved decision: runtime-first actor commit with asynchronous persistence and explicit failure warning. No rollback; latest config may be lost on crash before save.
- Exact-parent model/provider ceilings and bundled allowlists were introduced by this PR and conflict with the agreed deferred scope. Removing them preserves existing task model selection and generic plugin extensibility; it is not a claim of a secure effect sandbox. Keep model allow-policy, permissions and graph checks.
- Legacy ACP/headless coordinator mutation remains an explicit compatibility boundary until PR 9; managed actors must never use it as an execution authority. Shared interfaces must not accidentally break those clients.
- Storage coalescing and same-ID runtime replacement require ordering at both enqueue and acknowledgement. Reuse current checkpoint epochs/generations and prove ordering in tests; do not only filter UI events.
- Admission preparation still includes filesystem reads and async prompt requests. Keep it outside state locks; a preparing FIFO entry prevents configuration overtaking but must remain cancellable/removable. Full guest contribution versioning remains PR 7.
- Directory/history mutation semantics remain outside actor config, but removing directory config reservations changes their relationship to config changes deliberately: config can commit during a pending directory operation, and admission pins committed cwd. Preserve visible deferred behavior and do not claim a timed-out request was cancelled while it can still mutate.
- No outstanding operator decisions or accepted test-infrastructure gaps. Add minimal fixtures identified in Test Strategy as part of implementation.
