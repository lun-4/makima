## Goal

Implement PR 4 of `.agents/makima-issues/24-agent-system-deliverables.md`: each managed agent owns its effective configuration, queued turns retain immutable policy, model/mode changes are FIFO barriers, and all tool, MCP, write, and child-spawn paths obey one host-enforced authorization policy. Keep existing TUI, Lua session/task, ACP/headless, and native mode/audience interfaces working as adapters.

## Implementation Summary

Build on the landed PR 1–3 actor/manager (`maki-agent/src/actor`, `manager`). Introduce a per-node configuration with immutable `TurnPolicySnapshot` (model/provider, options, selected resolved mode, prompt inputs, tool bindings, permission/mutation/spawn ceilings), capture it at actor admission for both normal turns and TUI roots, and pass it through backend/run/tool contexts. Serialize setters with admission and stop root folding across policy generations. Use canonical resolved tool bindings for advertised tools and execution authorization, before existing permission prompts. Route UI/coordinator and Lua compatibility setters through agent configuration. Preserve native build/plan and audience behavior; do not implement the PR 5 first-class Lua API, PR 6 graph persistence, PR 7 guest mode/preset ownership, or PR 8 UI changes. Existing session metadata remains the persistence adapter until PR 6.

## Implementation Plan

1. **Establish the policy owner and admission contract (`maki-agent`).** Add per-agent configuration to manager-created actors, including selected provider/model pair, `RequestOptions` (thinking/fast), workflow, mode, prompt/system inputs, tool selection and effective restrictions. Expose explicit initialization for `create_root_with`/`spawn_child_with` and a narrowly scoped update path for existing frontends; avoid a mutable process-wide model owner. Keep shared clients/discovery and existing permission manager infrastructure. Represent a resolved immutable policy as an `Arc` with a monotonic generation; include the resolved `ModeDef`, plan path/write restriction, prompt fragment and tool catalog/bindings, audience, inherited child ceiling, relevant MCP scope, and selected model/provider, not mutable registry lookups. Admit using the actor state/queue lock so each `TurnAdmission` and `RootWork` receives a snapshot atomically relative to configuration changes; add `TurnContext` access for backend construction. Reject missing custom modes at admission/setter with a visible error, never silently use build (`maki-agent/src/modes.rs:196-219`). Preserve built-in fallback only for explicit build/plan adapter values. Keep `AgentInput` compatibility fields as inputs to the adapter at admission, not as execution-time authority. Validate model/provider and clamp options before committing a setter; on failure retain the previous generation. Ensure child configuration intersects the parent's active turn ceiling and cannot be widened by caller-supplied tools, audience, or mode. Relevant existing shape: `manager/mod.rs:187-313`, `actor/mod.rs:348-435`, `actor/types.rs:59-70,93-148`, `maki-lua/src/api/agent.rs:978-1158`.

2. **Serialize policy updates and protect running turns.** Implement one per-agent admission sequencer (mutex-protected ordered operation queue, independent of the execution queue) for both setters and submissions. A setter reserves its position synchronously when requested; concurrent admissions after that reservation wait on the setter's result rather than taking the old snapshot. Perform fallible provider validation/construction and coordinator checkpoint/adoption outside locks; serialize setter resolution in reservation order, then under the sequencer lock atomically commit the new configuration/generation *only on success*, resolve waiting admissions against the committed (or unchanged on failure) configuration, insert their turns/roots in reservation order, and acknowledge the setter. Before/after setter turns remain ordered in the execution queue; a failed setter removes its boundary without applying it, but must still separate roots whose effective generations differ. A pending setter must block interrupt extraction of post-reservation roots until resolved, without blocking active-turn progress; if necessary use a typed barrier marker in `ActorWork` that `pop_interrupt` never crosses, and resolve/remove it before normal runner pop. Never await while holding actor/graph/sequencer locks; use actor state then queue lock order and ensure close/shutdown resolve all pending admission/setter waiters. The acknowledgement is success/failure after commit, not fire-and-forget dispatch. Capture addressed `AgentId` at UI/Lua action dispatch; route UI actions, Lua `maki.model.set`, `maki.mode.set` and relevant session options through the sequencer, preserving existing Lua return shapes (mode may still acknowledge *request accepted*, while failure must emit a visible UI error). Snapshot options from one committed value, not separately from mutable slot and coordinator (`maki-agent/src/session_coordinator.rs:1697-1777`, `maki-agent/src/agent/run.rs:119-152`). Keep coordinator version validation/checkpointing and session-meta mode/model as projections of root configuration, not a competing execution authority. Test overlapping setter reservations, a long-running provider initialization, failure rollback, and an admission concurrent with each.

3. **Close root batching/interrupt escape routes.** Add policy generation to `RootWork` batch compatibility and interrupt extraction (`actor/queue.rs:78-120,258-284`); barriers and unequal generations stop both batch and active-turn folding. Do not fold a queued root with a different effective policy into a running turn even if its mode/workflow matches; leave it queued for its own turn. Preserve same-generation plain-text coalescing and same-policy interrupt UX where possible. Remove live `SessionRunSettings`/`adopt_pending_settings` changes during a turn (`agent/run.rs:484-563`, `maki-ui/src/agent/agent_loop.rs:319-352`) and prevent `handle_queued_command` from replacing the turn's mode (`agent/run.rs:855-885`). Continuations, compaction, system prompt and MCP/tool requests use the admitted snapshot; reloading cwd/instructions/prompt slots may change only a later turn. Resolve dynamic prompt slots/MCP prompt references before or at admission without silently widening the snapshot; if asynchronous resolution cannot complete there, pin dependencies at admission and return a typed setup failure if they disappear. Ensure TUI `prepare_run` does not reread current model/mode/tool policy (`agent_loop.rs:199-249`), while Lua `LuaActorState` remains an API adapter and each Lua turn uses its own admission policy (`maki-lua/src/api/agent.rs:332-352,1124-1151`). Update ACP/headless/SDK/print construction paths that create `AgentInput` to initialize agent config or use one compatibility initialization path.

4. **Centralize authorization at execution.** Replace the duplicated audience/filter decisions in `RequestTools::build`/`assembled`, `callable`, and individual dispatch routes with one canonical resolved-binding policy API. Bind local/native/MCP/search tools in `resolve` precedence (local > registry > MCP) with qualified MCP identity and pinned registration identity/generation; if replacement/reconnect changes a binding before dispatch, reject rather than rebind. Both offered schemas and `callable` derive from these bindings; dispatch resolves once, checks the *same binding* after input hooks rewrite the arguments and before start events/ordinary permissions, then executes that exact route. Check audience, model capability, disabled tools, mode exact toolset, inherited tool ceiling and MCP ceiling, including `functions.*`, local shadowing, deferred and previously loaded MCP tools (`agent/tool_dispatch.rs:79-117,287-388,429-516,676-813`). Authorization failures cannot be made approvable by YOLO or a permission rule. Preserve existing native/MCP permission prompts only after ceilings pass. Carry the same snapshot into nested `batch`/`code_execution`/`maki.agent.call_tool`, MCP discovery/loading/prompt expansion, and Lua child-spawn creation (including direct `maki.agent.session`, not just task-plugin checks); require a live managed turn to delegate, retain the explicit unmanaged compatibility route without granting managed parent authority. Keep manager graph limit/active-turn checks (`manager/mod.rs:271-369`).

   Define an explicit effect contract on host-owned native/local tools: `ReadOnly`, `FileMutation` with all normalized source/destination targets extracted from parsed final input, `DelegatedComposite` (each nested operation reauthorizes under the same snapshot), `Spawn`, or `UnknownMutation` (default for unannotated handlers and MCP, shell and arbitrary execution). Do not accept Lua plugin registration metadata as host-enforced read-only: a tool handler can call `maki.fs.write/rm` under plugin `FsWrite` regardless of `mutable_path` (`maki-lua/src/api/fs/mod.rs:451-522`, `api/tool.rs:1620-1641`). Preserve existing bundled read/glob/grep and plan-file write/edit by carrying the immutable turn policy into the Lua handler task and propagating it through `maki.async.run` and nested callbacks (`maki-lua/src/runtime.rs:1402-1428,1864-1871,4327-4343`); gate **actual host effects** at Lua FS mutation APIs (`write`, `atomic_write`, `rm`, `mkdir` and other effectful FS methods), process launch (`maki.fn.jobstart` at `maki-lua/src/api/fn.rs:425-518`, plus all other subprocess APIs), and any guest command/transport API that bypasses checked tool dispatch. Check at process creation, not just when the tool returns: a restrictive turn cannot start any process, including plugin-owned detached jobs that would outlive that turn. Tasks descended through `maki.async.run` retain their origin policy; detached jobs cannot shed it to start a process after the turn ends. Plugin-level permission remains necessary, never sufficient. An agent-origin effectful task without turn policy fails closed; non-agent plugin initialization/commands retain existing plugin permission semantics. Resolve plan-file parent creation without granting arbitrary directory writes, and recheck paths at the effect boundary; implement handle-relative safe mutation for allowed exact-file writes or deny unsafe operations, not a check-then-open authorization claim. Lua handlers may be advertised as read-only/composite only when their reachable host effectful APIs are mediated by that policy, including asynchronous descendants; unknown external side effects remain denied in restrictive modes. If a route cannot be safely mediated in this PR, hide and deny it in restrictive mode. Test a Lua handler falsely claiming read-only which calls `maki.fs.write` with plugin FsWrite granted: out-of-ceiling effect must be denied at the FS API, regardless of approval, including when invoked asynchronously. Keep unrestricted plugin behavior. In restrictive modes, `UnknownMutation` is denied before permissions; `DelegatedComposite` may run only if it cannot do side effects except via the checked dispatcher; every actual child call must pass authorization. `Spawn` uses the inherited child ceiling and is additionally enforced at the manager-facing Lua spawn boundary. `FileMutation` allows only targets inside the resolved exact-file ceiling; missing/erroring extractor denies, not read-only. Do not infer safety from `ToolInvocation::mutable_path == None` or `permission_scopes == None` (`tools/registry.rs:199-231`, `maki-lua/src/api/tool.rs:480-487`). Annotate trusted host-native implementations deliberately; do not whitelist bundled Lua callbacks solely because they ship in-tree. Unclassified third-party tools remain callable under unrestricted policy but unavailable in restrictive modes. MCP is opaque unless explicitly configured as read-only through a trusted host-side classification, never inferred from name or user approval. Preserve normal permission flow for unrestricted modes. For restrictive writes, keep only native plan-file operations whose actual filesystem execution can honor the target ceiling safely; if any route relies on unsafe path-only check-then-open for the claimed ceiling, deny it until a handle-relative execution adapter is implemented. Add symlink/TOCTOU tests for any newly supported file mutation category, and do not claim security from `mutable_path` checks alone. `maki-agent/src/tools/mod.rs:132-211,348-416`, `modes.rs:44-58`, `permissions.rs:395-439`, `plugins/task/init.lua:178-187`.

5. **Compatibility and documentation.** Map existing UI model/mode commands, status and checkpoint projections, Lua `maki.model`/`maki.mode` and `maki.agent.session`, and headless callers onto the new agent-owned settings; retain return/error conventions in `maki-lua/src/api/AGENTS.md`. Make UI-free `maki.model.get` with explicit agent/tool context return that agent's selected model; preserve UI-focused fallback for no context, and no-UI single-agent fallback where available (issue #27). Preserve existing built-in plan/build prompts and labels via `ModeDef` adapters, and task audiences without allowing audiences alone to grant authority. Update user-facing `site/docs/content/modes/_index.md` and `permissions/_index.md` to explain turn-boundary setters, queue behavior, and restrictive unknown-effect denial; update provider/model docs if model ownership is described there. No graph format migration or guest-mode versioning in this PR.

## Acceptance Criteria

- **AC.1** Two managed agents in one outer session, and two outer sessions, can use different model/provider/options simultaneously; a failed model switch leaves the addressed agent unchanged and other agents unaffected. A UI-free Lua model read with context returns that agent's model. Verified by `agent_config_isolation_and_failed_switch` and `lua_model_get_without_ui`.
- **AC.2** For turns queued A, setter, B, A retains the old model/mode/options/prompt/tools through every provider request and nested call, B uses the new policy; a failed setter leaves B on old policy. Cancelling A or closing while a setter waits does not deadlock. Verified by `queued_turn_policy_barrier_and_failure` and `pending_setter_cancellation`.
- **AC.3** TUI roots queued/rushed or folded during a running turn never batch/fold across a policy barrier, while same-policy eligible roots still batch; rendering and session projections agree with the selected agent. Verified by `root_batch_and_interrupt_respect_policy_generation` and `ui_queue_and_mode_model_projection`.
- **AC.4** For each advertised and indirect dispatch path, disallowed bindings (including stale/shadowed/aliased native, local, MCP, deferred tools) are neither advertised nor executable; an input-hook rewrite is checked after rewrite, and denial runs no handler/transport/permission prompt. Verified by `advertised_equals_authorized_bindings` and `indirect_dispatch_denials`.
- **AC.5** Restrictive modes allow only permitted known write targets, reject out-of-bound/unknown-effect calls even with YOLO or approval, and neither task nor direct Lua spawning can create a broader child; unrestricted build calls still use ordinary permissions. Verified by `restricted_effects_before_permissions` and `child_policy_intersection_end_to_end`.
- **AC.6** Existing TUI modes, Lua session/task behavior, and noninteractive frontend turns still run under the adapters; missing selected custom modes fail visibly rather than falling back to build. Verified by `adapter_turns_across_frontends` and `missing_mode_fails_closed`.

## Risks, Blockers, and Required Decisions

- **Decision from operator:** In plan mode, block shell commands entirely for now, even if the user would approve the call; a later change may revisit this. Enforce this for direct and indirect shell/process execution, not just the advertised tool list. Issue #61 favors normal per-call permissions, but this explicit decision governs PR 4. Treat unknown-effect MCP execution as denied under restrictive policy as already planned; only host-classified read-only MCP operations may run. This is a conservative implementation choice, not an operator decision about future MCP policy.
- The migration proposal `.agents/makima-issues/makima-mode-and-agents-into-guest.md:103-178` describes a much stronger capability lattice and anchored file-handle mutation; this PR implements the required invariant with narrower scoped bindings and conservative denial, not a claim that arbitrary path-only tools are race-proof. Where safe execution is unavailable, restrictive modes must deny rather than silently allow. Document and test the plan-mode shell/MCP behavior.
- Existing prompt slots, MCP discovery, cwd and mode registries are mutable; pin their effective values/identities for admitted turns and fail visibly when a dependency vanishes. Full transactional guest contribution generations belong to PR 7; do not silently rebind stale bindings.
- Setter ordering spans UI event handlers, session coordinator async commits, actor queue, and Lua. Avoid awaiting with graph/actor locks, preserve coordinator checkpoint/version behavior, and test concurrent completions without sleeps.
- PR 6 owns durable graph/config/queue persistence. PR 4 must keep existing session metadata accurate but cannot promise replay of each queued turn after restart; keep that limitation explicit rather than adding a new storage format here.
