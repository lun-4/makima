## Implementation Plan

### 1. Public identities and context authority

Expose Agent, visibility-only AgentRef, AgentTurn ticket and AgentSubscription userdata. Register docs using existing lua_class/lua_fn machinery and Pair runtime-error conventions. Runtime failures return nil,err; programmer argument-type errors may throw.

Public surface:

- maki.agent.current(ctx), root(ctx), list(ctx), get(ctx, ref), spawn(ctx, opts).
- Agent:id(), ref(); context-free immutable identity only.
- Agent:status(ctx), model(ctx), available_models(ctx), transcript(ctx, bounds).
- Agent:send(ctx, message, opts), enqueue(ctx, message), prompt(ctx, message, opts).
- Agent:set_model(ctx, patch), set_mode(ctx, name), cancel(ctx), cancel_subtree(ctx), close(ctx).
- AgentTurn:id(), agent_id(), result(ctx), wait(ctx, opts), cancel(ctx).
- AgentRef identity getters and authorized metadata reads only; no mutation methods. get(ctx,ref) resolves an Agent only when ctx has existing control authority.
- Typed on_turn_start/on_turn_end/on_idle/on_config_change/on_close methods, each taking ctx and a handler and returning a subscription.
- AgentSubscription:close() revokes its own registration and cancels active handlers; it cannot confer agent control.
- ctx:agent() returns the pinned subject/caller; ctx:model() reads an executing turn's admitted selection and returns an explicit unsupported-context error for command/event contexts with no executing model turn. ctx:defer_close(agent) registers host-managed cleanup after checking close authority.

Tool authority identifies manager/runtime generation, caller agent and executing turn; validate active captured/current authority for retained ctx operations. Control covers self and allowed descendants, not ancestor/sibling handles passed in by Lua. Revalidate after async preparation before commit/admission. Trusted command/event contexts identify plugin owner/generation and host scope, remain valid across awaits until handler exit, and expire on exit/unload. Agents spawned by those handlers do not inherit trusted authority: their model-driven tools receive restricted turn contexts. Use a safe optional coroutine-context accessor rather than public calls that panic outside TaskCell scope.

Commands receive ctx pinned to the UI-selected agent at invocation, not later focus. Selection may be root or child; do not claim full child promptbox migration. Provide explicit trusted focused-agent resolution for keymaps outside command invocation; no missing-target fallback in agent methods. Hosts supply resolver/service interfaces without Rust UI dependencies in Lua core.

References do not close agents on GC; explicit close closes the subtree. Manager/host shutdown handles final lifetime. Retired runtime identities fail even if textual IDs match replacements. Legacy Session retains close-on-drop. Tickets retain settled immutable results after owner GC/close without restoring mutation authority.

Keep standalone child support through existing unmanaged fallback, scoped to its host/owner. ACP, SDK, headless and print hosts supply an explicit stable root reference through a host-root adapter without inventing manager identities or migrating their execution loops. Root admitted-context reads and committed selection/discovery operate through the existing turn snapshot and coordinator/provider preparation services. ACP/SDK support coordinator updates with existing checkpoint/rollback semantics; fixed print/headless roots reject all model patches, including options-only, without changing projections. Unsupported graph, ticket or mutation operations fail explicitly; root references must not silently redirect to a spawned child or UI focus. Document and test the supported operation matrix. Preserve frontend execution loops until PR 9.

### 2. Admission, exact results and observation waits

send accepts only when no turn is active, preparing or queued; evaluate this and reserve admission atomically in actor FIFO. Pending configuration operations may precede accepted work, but pending work prevents a second nonqueueing send. Optional after_turn additionally requires that ID is the latest terminal turn. Failed preconditions return a typed busy/stale error without admission. enqueue accepts FIFO work while busy, but can still fail authorization, validation, lifecycle or limits. Both return exact tickets. prompt is send plus exact wait; task adapter may use enqueue plus wait where legacy FIFO behavior requires it.

Wait timeout means stop waiting only. Dropping a wait or ticket never cancels work. Positive timeout returns nil plus a timeout error; prompt includes its exact ticket in that error for resumed observation/cancellation; zero is nonblocking observation; invalid negative timeout is programmer/validation failure. Explicit ticket cancel is separate. Legacy Session:prompt preserves its existing destructive timeout and zero-timeout rejection through an adapter.

Return terminal result {agent_id, turn_id, status, text, usage, output?, error?, user_message?, cancellation_reason?}, with completed/failed/cancelled status and per-turn usage. Execution failure is a result; waiting/admission failures are nil,err. result(ctx) returns nil,nil while pending. Complete results are repeatable and immutable.

TurnOutcome currently lacks text and Lua presentation is consumed separately. Add actor-owned per-turn presentation accumulation through ActorTurnContext, shared by LuaActorBackend and TuiActorBackend. Capture accepted text/output before forwarding streaming events, not after asynchronous relays/backend return. Terminal settlement freezes outcome plus accumulated presentation under one synchronization boundary. Normal completion/cancellation/close compete; first settlement wins and late output writes are ignored. Queued/setup-failed turns have distinct empty accumulators. Immediate close preserves text captured before freeze. Define one lock order and never call external handlers under actor locks. Held tickets own their immutable settled result independently of actor lookup retention. Bound actor-owned outcome/ticket lookup caches and reclaim closed graph heavy resources; transcript coverage follows retained history boundaries rather than keeping duplicate full outputs forever. Evicted ID lookups return an explicit unavailable error, while held tickets remain readable. Do not introduce a global Lua result registry. Canonical turn text is the last assistant message, with partial text from an incomplete final message retained on failure/cancellation. Earlier narration remains in the transcript, not concatenated into the final answer.

Root-started turns currently skip retention (actor/runner.rs:363-368). Retain real started root completions and publish subscriptions without re-emitting existing Agent::run UI terminal events. Folded root input belongs to the active turn; removed root work before start does not invent a turn result. Test actual TUI backend paths, not only Lua children.

Parent descendant waits use TurnPermitLease to suspend/reacquire capacity. Add non-destructive timeout policy alongside compatibility close-on-timeout. Reject pending self/ancestor waits inside executing turns; allow settled reads. Trusted callbacks have no executing model permit and use ordinary ticket observation. Preserve ticket actor/runtime validation and permit cleanup on cancellation/drop.

### 3. Concurrent typed events and guaranteed cleanup

Events are future-only, no historical replay. Register atomically against actor settlement; deliver one attempt per applicable event/subscription. Dispatch all subscribers without awaiting callbacks. Invocations within one subscription may overlap too. Subscription GC does not revoke registration; explicit subscription close, plugin unload or host shutdown owns revocation. Host tracks tasks until completion; this does not suspend actor execution or unrelated handlers. Plugins implement their own locks/queues/generation checks. Ordering of callback completion is not guaranteed.

Use named typed handlers with documented immutable payloads: all events carry subject agent identity; turn events carry turn ID and host-stamped origin; turn_end carries the exact immutable result; config_change carries committed configuration generation/selection; close carries terminal lifecycle reason. turn_start includes effective turn selection. on_idle means transition to no active/preparing/queued turn work, not a reservation that prevents new input.

Origin distinguishes user, plugin and internal host work; plugin origin contains host-assigned plugin identity/generation. Stamp at admission, not from user-supplied data. Preserve provenance when projecting existing root input. Default coalescing must not erase distinct origins; constrain batching at origin boundaries where needed. An origin is provenance, not authority.

Add independent actor event subscription support; do not repurpose root-only synchronous autocmds as async agent handlers. Lua dispatch happens outside actor locks on its runtime thread, with fresh trusted callback ctx scoped to the plugin. Only trusted command/keymap/event contexts can register these trusted callbacks; delegated tool contexts are denied. Handler failures are logged/reported without rolling back settled operations. Replace the text/history-inferred parent relay with one structured runtime delivery attempt keyed by child agent and turn ID, targeting the recorded parent. The envelope carries compatibility task ID, agent/turn/parent identity, outcome, diagnostic/user error/retryability, cancellation reason, admitted configuration, origin/trace correlation, usage and exact text/output. Keep lifecycle provenance distinct from ordinary user input when rendering for the parent model; later parent mode/focus changes do not retarget or reinterpret it. TUI projects deliveries rather than creating them. No durable acknowledgement/restart delivery is promised.

Subscription close immediately disables future dispatch, discards pending deliveries and cancels all active handler tasks. Plugin unload/reload and host shutdown do the same. Cleanup registrations execute on return/error/cancellation with host-held cleanup capability independent of expired Lua ctx; repeated close is idempotent. defer_close validates the resource's runtime/authority at registration, retains the cleanup resource and closes it even if the callback coroutine is dropped. Avoid reference cycles and remove task/registration bookkeeping after settlement. Plugin-scoped async child jobs must retain explicit lifecycle ownership; merely copying an event ctx cannot extend its authority past handler completion. Parentage is separate from cancellation ownership: cancelling an executing turn closes only its turn-owned delegated children, not independently owned plugin agents. Explicit subtree cancellation/close remains recursive.

### 4. Spawn configuration, prompts, transcript and structured output

Resolve agent configuration before spawn succeeds. Omitted fields inherit parent's executing-turn snapshot for tool creation, and pinned target's committed configuration for trusted command/event creation. Explicit parent target must be authorized and validated before/after preparation. Copy configuration values, not authority; later parent changes do not change child selection.

Support system string using existing system_prompt/prompt-slot/instruction machinery; do not invent another composer or add reminder comments. Preserve existing build/mode framing and restrictive mode inheritance; document actual prompt contribution order and custom system behavior. Guest mode composition remains later work. Agent creation may have no initial message.

transcript(ctx, bounds) accepts {through_turn?, last_messages, max_bytes}; last_messages and max_bytes are required positive integers, with named host caps of 1000 messages and 1 MiB encoded messages. Reject limits above caps rather than silently changing them. Default through_turn is the latest terminal turn; an agent with no terminal turns returns an empty snapshot. Explicit pending/unknown turns return distinct pending/unknown errors. Capture the snapshot atomically, excluding messages after the requested terminal turn. Associate history entries with actor turn boundaries, preserving turn coverage metadata through compaction. If compaction removed the requested boundary, return transcript_unavailable rather than including later summary information. Latest snapshots may include compacted summaries, identified as such.

Return {agent_id, through_turn, messages, truncated, omitted_messages, omitted_tool_groups, compacted}. messages are copied read-only values containing role/content and tool correlation; never return mutable history handles. max_bytes counts UTF-8 bytes of canonical compact JSON encoding of the messages array (including delimiters), not envelope metadata. Select a newest suffix up to last_messages; treat assistant tool-call messages and their corresponding tool responses as indivisible groups. Expand a selection boundary only within both limits; otherwise omit the intersected group and increment omission metadata. Trim oldest complete units until the byte cap fits. Never split oversized messages/groups or return unmatched tool responses; if none fit, return empty messages with truncated=true and omission counts. last_messages counts logical messages including tool responses, not turns or provider chunks. Tests cover exact cap, multi-byte text, oversized groups, empty history, pending/unknown and compacted-away boundaries. Do not claim snapshots are an archive unaffected by compaction.

output_schema is spawn configuration applied to final results of each turn, not intermediate messages or normal tool inputs. Promote the task plugin's validated local structured_output reporting tool alongside permitted tools. Capture output into the exact turn accumulator. Preserve current bounded nudges/validation handling through shared implementation, rejecting invalid schema before spawn. Define completion as normal run completion with a captured valid result; reporting output does not itself bypass remaining tool/turn lifecycle. Missing/invalid final report yields a structured terminal failure after bounded recovery. Prevent outputs from a previous turn satisfying a later turn's schema.

### 6. Compatibility and deterministic integration fixtures

Session wraps shared child implementation, preserving boolean send, latest status, cumulative usage, exact prompt errors/partial text, legacy timeout, task/UI string IDs and close-on-GC. Legacy Session is an explicit compatibility capability, not an identity-only handle: it is restricted to the creating host/plugin generation and immutable policy ceiling, and revoked on unload/reload. Trusted creation supports later same-plugin handlers; delegated creation expires with the turn. Current coroutine authority is validated for context-free effects; userdata transfer does not transfer control. Shared construction registers ownership so retained userdata cannot keep an unloaded plugin child live. New runtime AgentId must not replace persisted compatibility history IDs.

Task plugin advertises `task_spawn` and `task_wait` as the standard async surface. Spawn returns immediately with task_id and turn_id; send retains task_id and adds the admitted turn_id. task_wait accepts task_id and optional turn_id, snapshots the latest admitted ticket once if omitted, and returns the deliberate task result projection. Timeout stops observation only. Concurrent sends never retarget an existing wait. Managed nested general agents may spawn descendants and wait using existing permit suspension/reacquisition, within graph/policy limits; no new scheduler is required. Keep `task` as a deprecated spawn/wait/close adapter and `task_get` as deprecated nonblocking observation, callable for compatibility but not advertised as preferred tools. Preserve legacy result fields, final-answer/partial-error text, retryability, cumulative usage and structured output. Verify baseline failed-send semantics and restore the promised adapter behavior without closing a target on mere authorization denial. Preserve unmanaged recursive blocking-task rejection until its semaphore safety is established. Use one Rust structured-output implementation for all task paths and one run-loop recovery-budget owner. Guest preset migration is PR 7.

Build reusable actual-plugin test host fixtures with in-memory filesystem and scripted fake LLM providers. Gates control request start, text emission, tool calls, output capture, preparation and cancellation; no sleeps. Drive tools and callbacks through production Lua coroutine/context paths. Tests must exercise actual request model/options/prompts/tool schemas, not just copied config slots. Provide a synthetic orchestration plugin fixture to exercise trusted events spawning fresh restricted children, investigation tools, structured results, concurrent callbacks and after_turn rejection without shipping /goal. This is required infrastructure, not a deferred gap.
