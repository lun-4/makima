## Goal

Improve slash-command argument autocomplete for large result sets, especially `/model`: Up and Down navigation wraps from either end of the complete candidate list, while the popup renders only a configurable fraction of the terminal height. Add the global UI setting `ui.autocomplete_height`, defaulting to `0.7`.

## Implementation Summary

Keep all matched command-argument candidates in `CommandPalette.argument_items`; limit only the rendered viewport so every candidate remains reachable. Add a scroll offset for the argument popup, update it whenever the selected candidate changes or the terminal viewport changes, and use cyclic selection for both Up and Down. The existing command-name palette already wraps and remains unchanged.

Add `autocomplete_height: f64` to the global `UiConfig`/`UiFileConfig` path. Extend the config metadata and generated-document machinery to represent a floating-point default and expose the Lua-facing type as `number`. Validate the setting as finite and in the range `(0, 1]`, then convert it to a row count at render time with a minimum of one row and a clamp to the space above the input. This setting applies to slash command-argument completion only; the separate `@` file/reference completion menu and its existing layout/cap remain unchanged.

Primary touch points:

- `maki-ui/src/components/command.rs`: argument selection wraparound, argument scroll state, capped viewport rendering, and focused unit/render tests.
- `maki-ui/src/app/view.rs`: pass the global autocomplete-height setting when rendering the command palette.
- `maki-config/src/lib.rs`: config parsing, merging, default, validation, and `UiConfig` metadata.
- `maki-config-macro/src/lib.rs`: floating-point `ConfigValue` metadata support.
- `maki-docgen/src/gen_config.rs` and generated `site/docs/content/configuration/_index.md`: expose and document the setting.
- `maki-ui/src/app/tests.rs`: integration coverage for argument navigation and rendered visibility where the existing app harness is useful.

Do not alter the unrelated pre-existing untracked `acp-command-effect-projection-handover.md` file.

## Implementation Plan

### 1. Extend UI configuration with a fractional height setting

1. In `maki-config/src/lib.rs`, add a named default constant for the fraction (`0.7`) near the other UI defaults. Add `autocomplete_height: Option<f64>` to `UiFileConfig`, include it in `UiFileConfig::merge`, and add the resolved `autocomplete_height: f64` field to `UiConfig`.
2. Add the field to `UiConfig` with `#[config(default = DEFAULT_AUTOCOMPLETE_HEIGHT, ty = "number", desc = ...)]` so generated configuration metadata advertises a Lua number and explains that it is a fraction of terminal height in `(0, 1]`. Do not use the existing integer `min` metadata because the valid range is fractional and has an upper bound.
3. Resolve the file value in `UiConfig::from_file`, preserving the default when omitted. Keep the value available through the existing `App.ui_config` path; no separate runtime state or per-palette configuration is needed.
4. Add a dedicated `ConfigError` variant and validation in `UiConfig::validate_all` for non-finite, zero/negative, or greater-than-one values. Keep validation in the existing `Config::validate` startup path. The error should identify `ui.autocomplete_height` and state the accepted range.
5. Extend `ConfigValue` with a floating-point variant and `format_default`, and teach `maki-config-macro`'s `ConfigSection` derive to emit that variant for the `number` metadata type. Preserve existing bool/integer/string behavior.
6. Update the generated configuration sample/template to show `autocomplete_height = 0.7`, regenerate `site/docs/content/configuration/_index.md`, and ensure the generated `ui` table documents the new field and range. Keep the docs concise and consistent with the existing configuration page.

### 2. Implement cyclic argument selection and a bounded viewport

1. In `CommandPalette`, add an argument-popup scroll offset (for example, `argument_scroll_offset`) and initialize/reset it with the other argument completion state. Mandate separate `command_selected` and `argument_selected` state: command operations and `sync_arguments` must use `command_selected`, while argument navigation, rendering, lifecycle, and acceptance must use `argument_selected`. Reset only argument selection/presentation state when a new completion result is applied, an argument completion is cancelled, the palette closes, or the test-only completion fixture replaces the list; keep the selected command identity intact through all argument-completion transitions.
2. Change the argument branch of `handle_key` so Up selects `len - 1` when the current argument selection is zero, otherwise decrements; Down selects zero when at `len - 1`, otherwise increments. Continue sending the normal Highlight lifecycle event after every movement. Leave command-name selection behavior as-is because its `move_up`/`move_down` helpers already wrap.
3. Add a small internal helper that, given the number of visible rows, clamps the argument scroll offset and shifts it just enough to keep `selected` visible. It must handle both ordinary movement and wraparound: moving from the first item to the last shows the bottom window, and moving from the last item to the first shows the top window.
4. Change `CommandPalette::view`/`view_arguments` to receive the configured height fraction from `App` (or an equivalent narrow parameter). When `input_area.y > 0`, compute `visible_rows = min(candidate_count, input_area.y, max(1, floor(frame.area().height * autocomplete_height)))`; the one-row minimum is an intentional exception to the raw-floor upper bound when the floor is zero but space exists. If `input_area.y == 0`, return `None` as today. Keep the integer conversions checked/clamped so the popup cannot overlap above the input or exceed the candidate count.
5. Render only the argument slice `[scroll_offset .. scroll_offset + visible_rows]`, but keep selection and Enter/Tab acceptance indexed against the full `argument_items` vector. Compare each rendered row's global index with `selected`, and keep candidate widths/ranking/acceptance based on the complete set so scrolling never drops candidates. Preserve a valid command selection for exact Enter acceptance: because the current `selected` field is shared by command rows and argument candidates, either introduce separate command/argument selections or restore/reset the command selection before `confirm_close(input)` after clearing an exactly accepted argument. This must work for a nonzero/offscreen argument selection and must not change normal argument acceptance.
6. Ensure a terminal resize or a changed configured fraction re-clamps the offset during rendering. Do not truncate candidates in `poll_arguments`; filtering, ordering, lifecycle callbacks, and acceptance must continue to operate over the full result list.
7. In `maki-ui/src/app/view.rs`, pass `self.ui_config.autocomplete_height` to the command palette render call. Do not pass the setting to `FileCompletionMenu` or change its existing 30%-of-terminal-height multi-column behavior.

### 3. Add focused regression coverage

1. In `maki-config/src/lib.rs` tests, cover the default value, parsing a fractional `[ui] autocomplete_height = 0.7`, overlay merge behavior, and rejection of zero, negative, greater-than-one, and non-finite values where the deserializer permits them. Test the existing two-stage lifecycle explicitly: parse/construct with `into_config(false)`, then call `config.validate()` and match the dedicated field-specific error; separately cover non-finite values by constructing `Config` directly if TOML deserialization cannot represent them. The startup-path `Config::validate()` result, rather than `into_config()` alone, is the rejection contract.
2. Add a concrete metadata/docs regression, such as `autocomplete_height_metadata_and_docs` in an existing testable crate or a small `maki-docgen` test harness. Assert that the `UiConfig::FIELDS` entry is named `autocomplete_height`, has type `number`, contains the `F64(0.7)` default, and describes the finite `(0, 1]` range and slash command-argument scope. Assert the generated configuration output contains the corresponding `[ui]` table row and the example `autocomplete_height = 0.7`. Retain `just gen-docs-check` as the checked-in synchronization check.
3. In `maki-ui/src/components/command.rs` tests, add a multi-item argument fixture and verify Up from index zero selects the final candidate and Down from the final candidate selects index zero. Verify lifecycle Highlight continues to target the newly selected candidate when a completion session is present.
4. Add a rendering test using Ratatui's `TestBackend` (following the existing popup rendering tests) that creates more candidates than the configured viewport, renders known terminal heights with `autocomplete_height = 0.7`, and asserts the exact formula `input_area.y > 0 => min(candidate_count, input_area.y, max(1, floor(frame_height * fraction)))`. Include explicit cases for `input_area.y == 0` asserting `None` and no popup rows, floor-zero/one-row minimum, available-space clamp, and candidate-count clamp. Move the selection across the viewport and assert the rendered labels change to the corresponding slice, including top/bottom wraparound.
5. Add an app-level regression in `maki-ui/src/app/tests.rs` proving the configured `UiConfig` reaches the command palette and that argument completion still accepts the selected item after it has been reached through a scrolled viewport. Use at least two matched commands with distinct completion behavior/context, select the second command, then select a nonzero/offscreen argument whose insertion exactly matches the current token, press Enter, and assert that the originally selected command and arguments are dispatched. Also exercise non-exact Enter followed by the second Enter and the Tab/Complete path: after each non-exact or Tab path, edit or move the cursor so a fresh `sync_arguments` request is issued, then assert its command name/identity and returned candidate before dispatch. Assert that the same command identity remains selected throughout all paths and subsequent argument synchronization still works. Preserve the existing named Enter/Tab and lifecycle tests.
6. Add unconditional regressions for the scope boundaries: a command-palette test such as `command_name_navigation_still_wraps` covering both directions, and an app/render test such as `at_completion_layout_ignores_autocomplete_height` that renders the same `@` popup with different UI fractions and confirms its existing geometry/visible-row behavior is unchanged.
7. Add a maki-lua/plugin-host regression for the public setup boundary, such as calling `maki.setup({ ui = { autocomplete_height = 0.7 } })` and asserting the resulting `RawConfig.ui.autocomplete_height`. If global/project merge behavior is claimed beyond the shared config merge test, use `load_init_files` with global and project init.lua fixtures; otherwise keep the merge acceptance wording limited to `RawConfig` merge semantics.

## Acceptance Criteria

- **AC.1**: With multiple command-argument candidates active, Up from the first candidate selects the last candidate and Down from the last candidate selects the first candidate; both directions emit the expected Highlight lifecycle event. Verified by `command_palette_argument_navigation_wraps_up_and_down` (or equivalent) in `maki-ui/src/components/command.rs`/`maki-ui/src/app/tests.rs`.
- **AC.2**: All candidates remain available for selection and acceptance even when more candidates exist than visible rows. Verified by `scrolled_argument_completion_accepts_offscreen_candidate`, which uses at least two matched commands with distinct completion behavior/context, selects the second command and an initially offscreen, nonzero-index argument whose insertion exactly matches the current token, presses Enter, and checks that the originally selected command and arguments are dispatched. The same regression covers non-exact Enter followed by the second Enter and the Tab/Complete path; after each non-exact or Tab path it edits or moves the cursor, asserts a fresh completion request still names the originally selected command and returns its candidate, and then asserts dispatch.
- **AC.3**: When `input_area.y == 0`, the argument popup returns `None`; otherwise it renders exactly `min(candidate_count, input_area.y, max(1, floor(window_height * ui.autocomplete_height)))` rows. The `max(1, ...)` clause intentionally permits one row when the raw floor is zero but space exists, while the other clamps prevent exceeding candidates or available rows above the input. Verified by `argument_completion_viewport_respects_height_fraction` with Ratatui `TestBackend` cases covering a large list, a short terminal, an available-space clamp, and a floor-zero/one-row minimum.
- **AC.4**: Selection movement keeps the selected candidate visible, including moving from the top to the bottom window and from the bottom to the top window; resizing/re-rendering clamps the offset without panic or stale rows. Verified by `argument_completion_scroll_follows_selection_and_resize`.
- **AC.5**: An omitted setting resolves to `UiConfig.autocomplete_height == 0.7`, `[ui] autocomplete_height = 0.7` survives parsing and `RawConfig` merge semantics, and the public Lua setup boundary accepts `maki.setup({ ui = { autocomplete_height = 0.7 } })`. Verified by `autocomplete_height_defaults_parses_and_merges` in `maki-config` tests and `lua_setup_accepts_autocomplete_height` in the maki-lua/plugin-host tests. Global/project loader behavior is included only if the implementation adds the corresponding `load_init_files` fixture coverage.
- **AC.6**: Invalid autocomplete-height values are rejected with a field-specific configuration error, including values outside `(0, 1]` and non-finite values where representable. Verified by `autocomplete_height_validation_rejects_invalid_values`.
- **AC.7**: Generated configuration metadata and the checked-in configuration reference expose `ui.autocomplete_height` as a number with default `0.7`, include an example `autocomplete_height = 0.7`, and describe it as the terminal-height fraction for slash command-argument suggestions. Verified by `autocomplete_height_metadata_and_docs` (asserting the `UiConfig::FIELDS` entry and the exact generated Markdown row under the `ui` section, including the field name, `number`, `0.7`, and description, plus the exact Lua example line) and `just gen-docs-check`.
- **AC.8**: Existing command-name wrapping, command-argument acceptance/lifecycle behavior, and separate `@` completion layout remain intact. Verified by `command_name_navigation_still_wraps`, `at_completion_layout_ignores_autocomplete_height`, `argument_completion_enter_fills_then_next_enter_executes`, `argument_completion_enter_on_exact_match_executes_immediately`, `empty_completion_cancels_once_and_next_request_uses_new_session`, the new multi-command acceptance regression, and `just check -p maki-config -p maki-config-macro -p maki-ui` (or the repository's equivalent scoped command).

## Risks, Blockers, and Required Decisions

- Fractional config support is not currently present in `maki-config-macro`; the plan explicitly includes the minimal `ConfigValue::F64`/macro/doc-generation extension rather than silently representing `0.7` as an integer or string.
- Terminal dimensions and the input area's position are `u16`; row conversion must use checked/clamped integer conversion and must not allow a zero-row popup when there is space to render one.
- The candidate vector must not be truncated to the visible slice, or `/model` candidates beyond the initial window will remain inaccessible. The scroll offset is presentation state only.
- The new setting intentionally applies only to slash command-argument completion. The `@` reference menu already has independent viewport/grid logic and is outside the selected scope.
- The repository starts with an unrelated untracked file, `acp-command-effect-projection-handover.md`; execution must leave it untouched.
